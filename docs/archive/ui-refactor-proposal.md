## 0. 决策摘要（给评审）

这次不是「换皮」，而是把界面从「模块拼贴的仪表盘」重构为「可操作的值班板」：**先排序异常，再展示全量；链路是第一位对象；高风险操作有统一的安全流程；所有对象可深链接。**

| # | 决策 | 内容 | 为什么 |
|---|---|---|---|
| 1 | 产品定位 | 单管理员、自托管、多服务器 xray 代理编排台；不是商业化多租户 SaaS | 与 `PRODUCT.md`、`README.md` 一致；避免引入不存在的权限/计费/租户概念 |
| 2 | 设计概念 | **线路值班台（Line Board）**：机群 = 站点，链路 = 线路，用户 = 通行证，订阅 = 时刻表 | 产品最独特的对象是「跨服务器、逐跳、有 revision 的链路」，当前界面没有把它作为第一对象 |
| 3 | 信息架构 | 5 个一级入口：**值班板 / 网络 / 访问 / 运行 / 设置**；旧路由全部重定向 | 现有 11 个平铺入口把「对象」和「工具」混在一起；5 个一级入口覆盖全部能力且可扩展 |
| 4 | 核心对象页 | 服务器、用户使用「列表 + 检查器」；链路使用「列表 + 独立详情页 + 编排器」 | 服务器/用户需要快速扫读；链路需要画拓扑、看 revision、做影响分析，必须有独立空间 |
| 5 | 视觉语言 | 暖纸/夜板中性色 + **信号蓝**（交互）+ **线路色**（身份）+ **状态色**（仅状态）；Barlow Condensed + Geist + Noto Sans SC Black；8pt 网格；12px 卡片圆角 | 与现有「发丝线 + 红色索引标签 + 0–2px 直角」明确区分；线路色让链路跨页面可识别 |
| 6 | 关键交互 | **变更安全四步**：意图 → 影响预览 → 执行（操作托盘）→ 验证；操作托盘不阻塞页面；`⌘K` 命令面板；筛选/选中写入 URL | 当前高风险操作靠弹窗和全屏进度层，用户会丢失上下文；长操作不可中断浏览是主要痛点 |
| 7 | 落地方式 | Phase 0–5，约 10–12 周（1 名前端 + 设计支持）；每阶段可独立发布；P0–P2 不改后端 API | 可评审、可回滚、避免大爆炸式重写；现有 API 已能支撑 90% 的新界面 |
| 8 | 验收底线 | WCAG 2.2 AA；5 个核心任务可用；1440/1280/1024/768/390 五档；浅深双外观；性能预算 | 设计系统必须以可验证的标准收口，而不是以截图好看收口 |

### 0.1 本方案明确不做

- 不引入第二套设计语言，不恢复 `hig` / `cream` / `patchbay` 或多主题注册表；只保留浅色/深色两个外观维度。
- 不新增前端依赖（不引入 React Router、React Query、CodeMirror、Chart.js、新的图标库）；复用现有 wouter、shadcn/Base UI、ECharts、lucide、GSAP。
- 不修改后端数据契约；P0–P2 的「待处理队列、影响分析、命令面板、筛选深链接」全部由现有列表/详情数据派生。
- 不把移动端做成完整编排工作台；移动端以「查看、确认、有限操作」为主，复杂链路编排引导到桌面端。
- 不在首屏加载 3D 地球、城市数据块或全套图表；这些能力保留但按需加载。
- 不虚构商业指标、客户、SLA 或性能基准；所有演示数据必须标注为合成数据。

## 1. 证据与约束（先读懂再设计）

### 1.1 产品事实

来自 `README.md`、`PRODUCT.md`、`docs/framework-design.md`、`docs/openapi.yaml` 的事实：

- Lattix 是**多服务器 xray 代理管理面板**：Backend 统一管理多台受控服务器（Agent），可视化创建代理节点、编排链路、分配用户与订阅、观察运行状态并执行维护。
- **单条 WebSocket 长连接**承担全部双向通信；Agent 主动拨出，Backend 永不外连。
- **虚拟配置模板下发**，Agent 落地为 xray 实际配置并上报生效值；节点/用户增删为零重启热操作，重启兜底 + 失败回滚。
- 能力覆盖：直连与中转（代理链 / NAT）链路、Reality 安全层、多格式订阅与分流模板、流量统计、事件告警、成本统计、配置漂移 reconcile、xray/agent 版本升级、服务器测试与探针监控、操作日志与请求日志、备份。
- 单管理员使用，**没有多角色权限体系**；界面中文；自托管 Linux；不商业化。
- 现有页面：登录、公开订阅、仪表盘、运行监控、服务器、成本统计、链路、用户、分组、订阅模板、外部订阅、操作日志、请求日志、设置。

### 1.2 领域对象与状态

这些对象决定了信息架构，不能被「页面」替代：

| 对象 | 关键事实 | 现有状态/字段（证据） |
|---|---|---|
| 服务器 Server | 一台受控机器；有地区、地址、机器类型（独立 IP / NAT）、端口段、标签、agent/xray 版本 | `connection_state`：`never_connected/connecting/reconnecting/online/offline/auth_rejected`；`config_drift`；`agent_settings_status` |
| 链路 Chain | 直连是 1 跳，中转是 2–4 跳；客户端只看到入口；有稳定 revision | `status`：`pending/applying/active/degraded/failed/waiting_for_agent/active_unconfirmed/active_failed/cleanup_pending/invalid/deleted`；`published_revision_id` / `desired_revision_id` / `revision_forced` / `endpoint_status` |
| 跳 Hop | 入口/中转/出口；每跳有 server、role、port、状态、错误 | `role`：`entry/middle/exit`；`status`：`pending/applying/active/failed` |

| 订阅模板 | 分流规则模板；可分配给用户 | `subscription/templates`、`assign/unassign`、`refresh` |
| 外部订阅 | 第三方订阅导入；节点独立落库；按订阅整体引入 | `external_subscriptions`、`external_chains`、同步状态/错误 |
| 日志 | 操作日志与请求日志，独立容量与查询 | `log/list-operations`、`log/list-requests` |
| 成本 | 服务器计费、汇率换算、已生效/计算成本 | `billing/stats`、`billing/stats/estimated` |
| 操作观察 | 长操作旁路观察；前端轮询进度 | `observe_id`、`/api/observe-task/get` |

### 1.4 硬约束（评审时不要推翻）

1. **不依赖外部字体或资源 CDN**；生产可走 Cloudflare，但前端不得引用公共 CDN（`docs/frontend.md`）。
2. **深色是默认外观**；浅色必须完整可用；首屏加载前应用外观，避免闪白（`index.html`）。
3. **全站中文文案**；英文只用于机器标识、协议、端口、版本、命令、链路代号等。
4. **保留现有 React SPA、业务功能、数据契约**；可以重排布局与导航，不能改 API 语义。
5. **单管理员**；不设计多角色权限、租户切换、团队协作。
6. **可访问性**：键盘导航、可见焦点、语义化状态、足够对比度、尊重 `prefers-reduced-motion`。
7. **不虚构**：没有证据的商业声明、客户、SLA、性能基准一律不写。
8. **状态机一致**：`panel` 与 `agent` 各有状态机；UI 只展示/触发已有状态，不发明新的状态迁移（`AGENTS.md`）。
9. **优先复用**：`requester`、`use-polling`、现有 provider、现有 shadcn 原语、现有 ECharts 封装；不新增实现。

## 2. 产品定位与用户

### 2.1 定位

**一句话**：Lattix 是自托管代理基础设施的「值班板 + 编排台」——它让一个管理员在多台服务器之间看清每条链路、每个用户和每次变更，并能安全地完成日常运维。

**价值主张**：

- **看清**：机群、链路、用户、订阅、成本、日志在一个控制面里，状态优先、异常可排序。
- **编排**：把「入口 → 中转 → 出口」的跨机链路画出来，按 revision 部署，失败可定位到跳。
- **交付**：把链路分配给用户，生成多格式订阅，发布结果可预览、可解释、可追溯。
- **安全**：高影响操作有影响预览、进度、结果与审计；不靠记忆和弹窗。

**不是什么**：不是多租户 SaaS、不是机场售卖前端、不是通用监控平台、不是 xray 配置编辑器。它服务于「自己部署、自己维护」的基础设施管理员。

### 2.2 用户分层

`PRODUCT.md` 已明确：**单管理员使用，没有多角色权限体系**。因此这里不做虚构的「运维/开发/财务」多角色，而是把同一个管理员的工作模式分层——这决定同一套 IA 如何在不同任务下切换焦点。

| 工作模式 | 何时出现 | 目标 | 频率 | 设计含义 |
|---|---|---|---|---|
| **值班者 Operator** | 每天打开面板、收到告警、例行巡检 | 快速判断「哪里坏了、影响谁、先做什么」 | 最高 | 值班板、异常队列、状态优先、操作托盘 |
| **编排者 Builder** | 新增/调整链路、协议、端口、Reality、NAT | 把拓扑安全地部署出去，失败能定位到跳 | 中 | 链路详情、编排器、revision、逐跳进度 |
| **发放者 Dispatcher** | 新用户开通、分配链路、交付订阅、处理客户端问题 | 让用户拿到可用的订阅，且知道哪些没纳入 | 中 | 用户详情、权限矩阵、订阅预览、二维码/复制 |
| **复盘者 Auditor** | 月末成本、故障复盘、审计变更 | 解释「钱花在哪、变更何时发生、谁受影响」 | 低 | 成本矩阵、操作日志、请求日志、revision 历史 |

> **假设 A1**：典型规模为 3–50 台服务器、5–100 条链路、100–5,000 个用户。若实际规模远大于此（如 500+ 服务器或 10 万用户），列表虚拟化、全局搜索与服务端筛选需要提前到 P1。
>
> **假设 A2**：团队规模为 1 人；若未来出现 2–3 人协作，需要新增只读/运维角色与审计视图，届时 IA 需重审。
>
> **假设 A3**：桌面端（≥1280px）是主要工作场景；移动端主要用于查看、确认与少量操作。该假设与 `PRODUCT.md` 的 Operating Context 一致。
>

## 3. 核心场景

### 3.1 场景一：早晨 5 分钟巡检（Operator）

- **触发**：上班打开面板，或手机收到离线告警。
- **现状**：仪表盘有 8 个模块；异常是一个数字；需要自己判断先看服务器还是链路。
- **新流程**：
  1. 值班板第一屏是「待处理」队列：按严重度排序，每条显示对象、原因、影响面、持续时长。
  2. 第一条是「HK-DE-US 三段跳 · 降级 · 影响 42 位用户」；点击就地展开「为什么」和三个动作：重试失败跳 / 打开服务器 / 查看受影响用户。
  3. 处理完，条目在队列中消失；右侧「机群脉搏」保留 24h 趋势与同步时间。
  4. 没有异常时，显示「当前无待处理事项」+ 最近一次检查时间 + 「查看操作日志」。
- **成功信号**：管理员在 1 分钟内说出「哪条链路、哪一跳、影响谁」。

### 3.2 场景二：夜间降级（Operator）

- **触发**：入口或中转 Agent 离线，链路 `degraded`，客户端仍可用但可能绕路。
- **现状**：链路卡片显示「降级」，但需要点进多个弹窗才能看到哪一跳离线、哪些用户受影响。
- **新流程**：
  1. 链路详情顶部状态条直接显示「降级 · 入口 HK-01 离线 · 已发布 revision 保持生效」。
  2. 拓扑画布把失败跳标红，连接线显示「保留旧路径」；右侧「影响面」显示受影响用户/分组/订阅。
  3. 动作区只给一个主操作「重试该跳」，次操作「打开服务器」「强制发布（谨慎）」。
  4. 点击重试 → 操作托盘显示逐跳阶段；完成后顶部状态变为「正常」，并在 revision 时间线留下记录。
- **成功信号**：不离开链路页即可完成定位与重试。

### 3.3 场景三：新建三段跳链路（Builder）

- **触发**：新增一条 `HK → JP → US` 的中转链路。
- **现状**：长弹窗里选服务器、协议、端口、Reality、名称模板；没有拓扑预览，也没有部署计划。
- **新流程**：
  1. 编排器第一步「画线路」：选择直连/中转，按顺序添加站点；线路实时预览；系统即时校验（重复服务器、跳数上限、入站能力、NAT 角色、端口冲突）。
  2. 第二步「定协议」：协议/安全/传输/端口/Reality dest；高级项折叠；名称模板带变量补全与预览。
  3. 第三步「看影响再发布」：显示「将部署 3 跳、影响 0 位用户、预计 40 秒」；可保存为未发布或直接发布；发布时按出口→入口顺序展示进度。
  4. 完成后进入链路详情，顶部给出「下一步：分配用户」。
- **成功信号**：创建前能看到拓扑和部署计划；失败时知道是哪一跳。

### 3.4 场景四：新用户开通（Dispatcher）

- **触发**：新增一个用户，需要 3 条链路 + 一个订阅模板。
- **现状**：创建用户、分配链路、订阅设置分散在多个弹窗/页面；容易漏掉链路或模板。
- **新流程**：
  1. 创建用户三步：身份（名称/有效期/试用）→ 权限（链路矩阵 + 分组 + 外部订阅）→ 订阅（模板/格式/更新间隔）→ 复核。
  2. 复核页显示「将生成 3 条链路、1 个模板、跳过 1 条未发布链路」；直接创建并发布。
  3. 结果页给出订阅地址、二维码、导入链接、分享链接；可复制/下载二维码。
  4. 若发布有警告，列出「哪些链路未纳入、原因、去哪里修」。
- **成功信号**：一次完成，且知道订阅里有什么、没有什么。

### 3.5 场景五：月末成本复盘（Auditor）

- **触发**：月末核对服务器支出与续费。
- **现状**：成本页有图表与矩阵，但和服务器详情/续费动作分离。
- **新流程**：
  1. 成本页顶部选择周期、报告币种、粒度；切换「已生效 / 计算成本」。
  2. 汇总卡显示总额、日均、服务器数；下方矩阵按服务器列出金额、状态、下次续费。
  3. 点击服务器行 → 服务器检查器「费用」分区；可直接「续费确认」。
  4. 汇率来源、自定义锚点、数据日期在页面底部可查。
- **成功信号**：从总额到具体续费不超过 2 次点击。

### 3.6 场景六：订阅排障（Dispatcher / Operator）

- **触发**：用户反馈「订阅导入后没有节点」。
- **现状**：需要去用户页看订阅、去链路页看状态、去模板页看规则，信息分散。
- **新流程**：
  1. 用户详情「订阅」分区直接显示：快照 revision、最后发布时间、格式、条目数、警告。
  2. 警告「2 条链路未纳入：1 条未发布有效 revision、1 条条目构造失败」；每条可跳到链路详情。
  3. 「预览」按格式/阶段查看生成结果；「重新生成」走操作托盘。
  4. 如果用户被停用/到期/未生效，状态条解释「为什么没有节点」以及恢复方式。
- **成功信号**：在一个页面内解释「为什么没节点、怎么修」。

## 4. 信息架构与导航

> 承接第 0 节决策 3–4 与第 2 节的工作模式分层。信息架构只解决三件事：**对象在哪、异常先看谁、链接能否复现**。现有 11 个平铺入口见 `src/frontend/src/components/Layout.tsx:30-66`；以下导航替换它，但保留全部业务能力。

### 4.1 组织原则

1. **对象优先，工具退后。** 一级入口按「值班 → 网络 → 访问 → 运行 → 设置」排列；服务器、链路、用户是对象，成本、日志、模板是工具或配置。
2. **最多两级导航。** 一级入口固定在左侧栏；二级入口只显示当前域的页面；对象详情用面包屑和页内分区承载，不再增加第三级侧栏。
3. **URL 即状态。** 筛选、选中、分页、页内视图全部可分享、可刷新；列表查询变化使用 `replace`，进入对象详情使用 `push`。
4. **高风险动作有固定落点。** 删除、强制发布等确认沿用 `useAppDialog`；长操作进入操作托盘，不再用全屏遮罩阻断浏览（现实现见 `src/frontend/src/components/OperationProgress.tsx:31-135`）。

| 页面 | 筛选参数 | 选中 / 视图 | 分页 / 排序 |
|---|---|---|---|
| 值班板 `/board` | `queue=all\|critical\|warning`、`since=12h\|24h` | 无 | 无（队列最多 8 行，展开内联） |
| 服务器 `/network/servers` | `q`、`state`、`region`、`tag`、`drift=1` | `sel=<id>` | `page`、`pageSize`、`sort=name\|state\|cpu\|latency\|created` |
| 链路 `/network/chains` | `q`、`state`、`type=relay\|direct\|node`、`server=<id>` | `sel=<id>`（返回时高亮） | `page`、`pageSize`、`sort=severity\|name\|updated` |
| 用户 `/access/users` | `q`、`state`、`chain=<id>`、`group=<id>` | `sel=<id>`、`view=list\|assign` | `page`、`pageSize`、`sort=created\|name\|expiry` |
| 日志 `/run/logs/*` | `severity`、`category`、`server`、`q`、`from`、`to`（请求日志另有 `method`、`window`） | `entry=<id\|request_id>` | `page`、`pageSize` |

规则：

1. **列表查询一律 `replace`**：搜索、筛选、排序、翻页、选中都不新增历史条目；浏览器后退离开列表页，不会逐行回放。进入 Chain/Node 详情用 `push`，后退可回到带原筛选的列表。
2. **搜索**：输入 250ms 防抖；trim 后最多 80 字符；空值移除参数。`/` 聚焦搜索框，仅在非输入控件内生效。
3. **数组**：逗号分隔，按枚举固定顺序输出；非法值丢弃并 `replace` 重写 URL，保留其余合法参数，不整页重置。
4. **选中**：`sel` 始终是单个整数；对象不存在时移除 `sel`、保留筛选，并在列表头显示「对象不存在或已删除」的 `Notice`。
5. **分页**：1 基；第 1 页省略 `page`；`pageSize` 允许 25/50/100，默认 50，省略默认值。筛选变化重置到第 1 页；页码越界时钳制到末页并 `replace`。日志用服务端 `offset/limit/total`（`src/frontend/src/pages/OperationLogs.tsx:118-138`）；其余列表当前接口一次返回数组（`src/frontend/src/pages/Chains.tsx:132-136`），在 A1 规模内做客户端分页，超过 A1 时再列 P3 服务端分页。
6. **排序**：默认值不写入 URL。服务器默认 `name asc`；链路默认 `severity desc`；用户默认 `created desc`；日志固定时间倒序。用户显式排序后才写 `sort`。
7. **不应放进 URL 的状态**：表格密度、刷新间隔、最近命令面板记录可放 `localStorage`；现有日志页已用 `lattix.logs.*` 存分页与刷新（`src/frontend/src/pages/OperationLogs.tsx:107-116`）。筛选不写入 localStorage，避免分享链接与本地状态不一致。

### 4.6 面包屑与返回

- 面包屑仅在**选中对象、设置分区、第三级路由**出现，例如「网络 / 链路 / HK-JP-US」「网络 / 链路 / HK-JP-US / 编辑拓扑」「服务器 / HK-01」「设置 / 安全通知」「运行 / 日志 / 操作日志」。无选中的一级/二级列表页不显示，避免「网络 / 服务器」这种与侧栏重复的双标题。
- 结构：32px 高、12px 字号；父级为链接（`ink-2`），当前项 `aria-current="page"`、ink 色；分隔符为 12px chevron，`aria-hidden`；最多 4 级。
- **返回键行为**：对象详情页的「返回」优先 `history.back()`，回到原列表 URL（含筛选与 `sel` 高亮）；直接打开深链接、没有同源来源时，`replace` 到该资源的规范列表。面包屑父级使用 `push`；若同一会话存在该资源的上次列表 URL，则恢复它，否则去规范列表。
- **检查器关闭**：Esc 与关闭按钮等价，用 `replace` 移除 `sel` 并保留筛选，焦点回到触发行；浏览器后退不关闭检查器，而是离开列表页（选中不写历史）。对象详情页 Esc 不关闭页面，只有编排器/检查器/命令面板响应 Esc。
- **编排器返回**：有未提交修改时弹出「继续编辑 / 放弃修改」；放弃才允许返回。浏览器后退与关闭标签页同样拦截（内部导航用应用对话框，关闭标签页用 `beforeunload`）。
- **登录返回**：`/login?next=<当前 path+query>`；登录成功后仅接受以 `/` 开头且不以 `/login` 开头的路径，否则去 `/board`。

### 4.7 空态、错误态与权限外

单管理员产品没有角色权限（`PRODUCT.md:11`），因此不存在「某个按钮无权限」；所谓权限外只有**未认证、会话过期、面板不可用**三类。

| 场景 | 呈现 | 主动作 |
|---|---|---|
| 未登录 / 401 | 跳 `/login?next=…`；登录页顶部说明「登录已过期，请重新登录」 | 登录后回原页 |
| 面板更新中 | 顶栏 `UPDATING`；全屏 `UpdateOverlay` 阻断操作，阶段与重启等待沿用现有实现 | 等待自动刷新 |
| 面板故障 | 顶栏 `FAULTED` + 主内容顶部横幅「面板状态异常：{fault}」；数据标注上次同步时间 | 打开「设置 / 系统维护」 |
| 接口失败 | 页级 `Notice tone="danger"`，显示 `RequestError.message`，可展开 request_id / trace_id；保留已加载数据 | 重试 |
| 无服务器（值班板/网络） | 值班板显示三步接入清单：接入服务器 → 创建链路 → 创建用户；网络服务器页空态 | 添加服务器 |
| 无链路 | 链路页空态；若服务器为 0，创建按钮禁用并说明「需要至少 1 台服务器作为出口」 | 添加服务器 / 创建第一条链路 |
| 无用户 | 用户页空态；说明「没有已发布链路时仍可创建用户，但订阅为空」 | 创建用户 |
| 筛选无结果 | 列表内空态，保留筛选条件与「清除筛选」；不显示首次接入引导 | 清除筛选 |
| 未选择对象 | 检查器空态：对象类型图标 + 「从左侧选择…」+ ↑↓ 快捷键提示 + 当前域 3 个统计值 | 无 |
| 对象不存在/已删除 | 列表内 `Notice` 并移除 `sel`；详情页显示「链路不存在或已删除」+ 返回列表 + 「查看已删除」筛选 | 返回列表 |
| 直连节点被删除 | 详情页只读终止态，不提供编辑；说明独立节点已无编辑 API | 返回列表 |
| Agent 离线导致操作不可用 | 按钮 `disabled` + 原因文案（如「Agent 离线，测试将在重连后执行」），不弹权限提示 | 打开服务器 |

## 5. 关键页面设计

> 本节只定义**页面骨架、优先级、状态与交互边界**；颜色/字体/阴影的最终值由第 6 节视觉系统给出。所有页面复用现有 `requester`、`usePolling`、`OperationProgressProvider` 与 `PagePrimitives`，不新增请求库或状态库。

### 5.1 值班板、网络域（服务器 / 链路）

#### 5.1.1 值班板 `/board`

**目标**：30 秒内回答「哪里坏了、影响谁、先做什么」。它不是仪表盘拼贴；现有 8 模块布局（`src/frontend/src/pages/Dashboard.tsx:351-852`）被替换为「队列 + 脉搏 + 变更」三段。

**骨架（1440×900）**

| 区域 | 尺寸 / 位置 | 首屏优先级 | 内容 |
|---|---|---|---|
| 页头 | 64px，内容顶部 | P1 | 「值班板」+ 日期 + 最后同步 + 刷新；右侧「N 项待处理」 |
| 待处理队列 | 776×624，左上 | **P0** | 最多 8 行，每行 56px；行内展开「为什么 / 影响 / 动作」 |
| 机群脉搏 | 360×624，右上 | P1 | 24h 吞吐折线（`/api/stats/traffic/series`）、在线/总数、漂移数、同步时间 |
| 最近变更 | 1160×自适应，下方 | P2 | 过去 12h 操作日志（`/api/log/list-operations?limit=20`），按对象分组 |
| 快捷操作 | 仅空态出现 | P3 | 添加服务器 / 创建链路 / 创建用户 |

首屏在 900px 高度内必须完整显示队列前 8 行与整个脉搏模块；「最近变更」允许在首屏下缘被截断，但不得把队列推到折叠线以下。

**队列行规格**：56px 高；列宽 32（类型图标）/ minmax(220px,1.4fr)（对象）/ 1.2fr（原因）/ 120（影响）/ 96（持续时长）/ 自适应（动作）。对象列显示名称 + 类型标签（服务器/链路/节点），原因列最多 2 行、超出省略并在展开区全文显示；影响列显示「42 位用户」，无法取得时显示「影响面未知」而不是 0。动作列最多一个主按钮 + 一个「更多」菜单。

**排序与分级**：

- **P0（故障）**：服务器 `offline/auth_rejected`，链路 `failed/active_failed/invalid`。
- **P1（降级/待处理）**：链路 `degraded/waiting_for_agent/cleanup_pending`，服务器 `config_drift/agent_settings_status=failed`。
- **P2（进行中）**：链路 `pending/applying`、节点 `pending/applying`、`active_unconfirmed`。
- 先按 P0→P1→P2，再按影响用户数降序，再按持续时长降序；同分按对象名。进行中的链路不进入 P0，即使它尚未生效。

**数据派生**：复用现有页面已经做的「服务器 + 链路 + dashboard」三请求（`src/frontend/src/pages/Dashboard.tsx:171-180`），事件派生逻辑参考 `src/frontend/src/pages/Dashboard.tsx:254-283`。影响面需要对 `/api/user/list` 做客户端 join：按 `chain_ids/effective_chain_ids/node_ids` 找到直接分配、分组派生与生效用户，按 user.id 去重；若用户列表请求失败，整列显示「影响面未知」，不得显示 0。A1 规模（100–5,000 用户）内可接受；超出时列为 P3 服务端聚合。

**空态**：无待处理事项时，队列区显示状态绿点 + 「当前无待处理事项」+ 最后检查时间 + 「查看操作日志」；不显示空白卡片。无服务器时，队列区替换为三步接入清单，主按钮「添加服务器」，次按钮「了解链路」。

**刷新**：10 秒静默轮询；页面隐藏时暂停，回到前台立即刷新一次。复用 `usePolling`（默认 5 秒，见 `src/frontend/src/lib/use-polling.ts:7-27`），为值班板传 10,000ms 并加 `visibilitychange` 守卫；不要另写 `setInterval`。

#### 5.1.2 服务器 `/network/servers`

**布局**：列表 + 检查器。≥1440：列表自适应 + 400 检查器 + 24 间距（内容 1160 → 列表 736）；1280–1439：检查器 376；1024–1279：检查器变为 480 右浮层；<1024：列表全宽，选中后进入全屏检查器页（URL 仍为 `?sel=<id>`）。

**列表骨架**

- 页头 64px：标题「服务器」+「12 台 / 10 在线 / 1 漂移」摘要（一行文本，不做统计卡）+ 主按钮「添加服务器」。
- 筛选条 48px：搜索 320px、状态多选、地区、标签、漂移开关、密度切换（44/36）、刷新；滚动时吸顶，表头吸在筛选条下（40px）。
- 表格：表头 40px，行默认 44px（紧凑 36px）；默认列依次为 服务器（别名 + #id）、连接、地区/位置、CPU、内存、磁盘、延迟、速率↑/↓、版本、告警。地址、标签、费用、最近上报为次级列，<1440 隐藏。
- 状态列使用状态令牌 + 文案：`在线/连接中/重连中/离线/未连接/凭据被拒绝`（`src/frontend/src/lib/server-state.ts:9-24`）；`config_drift` 与 `agent_settings_status=failed` 各给一个可筛选的告警标记，不合并成「异常」一个词。
- 排序：别名、连接状态（在线优先）、CPU、延迟、创建时间；默认别名升序。空值始终显示 `--`，不显示 0。
- 首屏：1440×900 下至少显示 12 行；不把检查器内容挤进表格。

**检查器规格（400px）**

- 结构：56px 头部（对象名 + 状态 + 关闭）→ 可滚动主体 → 64px 底部操作条。检查器自身 `position: sticky`，高度 `calc(100dvh - 56px - 48px)`，主体独立滚动。
- 分区顺序：**概览**（连接、地址、Agent/Xray 版本、机器类型、标签）→ **指标**（CPU/内存/磁盘/延迟，1h 趋势用现有 metric history）→ **链路**（引用此服务器的 Chain + 独立 Node，按入口/中转/出口排序）→ **费用**（计费周期、下次续费、状态）→ **运维**（测试、升级 xray/agent、修复、清理、重建、轮换 token、删除）。
- 操作条：主操作随状态变化（离线→「修复 / 查看命令记录」，在线→「编辑」）；测试、升级、删除收进「更多」，删除为危险项。现有详情抽屉主体可直接迁移（`src/frontend/src/components/ServerMonitor.tsx:1088-1382`）。同一列表-检查器规格用于 `/access/users`，具体分区由 5.2 节细化。
- 未选中状态：不自动选中第一台（与现实现 `src/frontend/src/components/ServerMonitor.tsx:1403-1405` 不同），显示「未选择服务器」+ 当前 3 个统计值 + 「↑↓ 选择」；这样 URL 与界面一致，深链接不会伪装成用户选择。
- 键盘：列表获得焦点后 ↑↓ 改变 `sel`（`replace`），Enter 把焦点送入检查器，Esc 关闭检查器；鼠标点击行同样只改 `sel`，不改变历史栈。

**移动端**：每台服务器一张 104px 卡片（名称/状态/地区/延迟/告警），点击进入全屏检查器；操作条固定在底部，危险操作在「更多」中二次确认。

#### 5.1.3 链路列表 `/network/chains`

**对象边界（必须保留现有事实）**：链路页同时承载两类对象：Chain（1 跳 = 直连，2–4 跳 = 中转）与独立 `XrayNode`（存量对象，无 revision）。现实现把 Node 与 Chain 混排并排除作为 relay exit 的 Node（`src/frontend/src/pages/Chains.tsx:276-300`）；新列表保留这一去重规则，但用类型标签区分「直连 / 中转 / 独立节点」，独立节点组默认折叠，数量为 0 时不渲染。

**行规格**：72px；左起状态标记、名称 + #id + 类型、迷你拓扑（最多 4 格，每格 48×28；<1280 显示前 2 格 + `+N`）、影响用户数、流量（有效值，倍率≠1 时在悬浮/展开显示原始值）、发布状态（`published/desired`，仅 Chain）、操作菜单。点击整行进入详情；列表不使用检查器。`sel` 只用于从详情返回时高亮，不打开侧栏。

**首屏优先级**：页头与筛选（P0）→ 前 8 行（P0）→ 状态汇总（P1，文本形式）→ 分页（P2）。默认按严重度排序：`failed/active_failed/invalid` → `degraded` → `waiting_for_agent/cleanup_pending` → `applying/pending` → `active_unconfirmed` → `active` → `deleted`。用户选择显式排序后，异常不再强制置顶，但状态标记仍保留。

**快捷筛选**：全部 / 异常 / 部署中 / 正常；映射 `state` 参数，计数来自当前列表。搜索覆盖名称、入口服务器别名、出口服务器别名、#id；不搜索错误正文（错误在详情诊断区）。

**空态**：0 台服务器时，主按钮「添加服务器」，创建链路按钮禁用并给出原因；有服务器但 0 条链路时，主按钮「创建第一条链路」，次按钮「直连与中转的区别」（打开说明面板，不跳外部文档）。

#### 5.1.4 链路详情 `/network/chains/:id`（独立页）

**骨架（1440）**：面包屑 32 → 状态头部 96（sticky）→ 主体 1160：主列 776 + 右栏 360。状态头部包含：返回、线路色 4px 标记 + 链路名、`#id`、直连/中转标签、状态、`published/desired` revision、强制发布标记、动作组。主列：拓扑面板 320 高 → 页内 tab 44 → 内容（影响 / 当前批次 / 流量 / 诊断）；右栏：影响面、发布状态、危险区。

**动作矩阵**（只允许现有 API；不发明逐跳重试）：

| 状态 | 主操作 | 次操作 / 菜单 | 规则 |
|---|---|---|---|
| `active` | 编辑拓扑 | 流量历史、重置流量、删除 | 正常态 |
| `failed / active_failed` | 重试链路（`/api/chain/retry`） | 编辑配置、强制发布（`desired≠0`）、删除 | 失败跳置顶并标红 |
| `degraded` | 打开离线服务器（有离线跳时），否则「查看诊断」 | 重试链路（有失败跳时）、强制发布 | 横幅说明「已发布 revision 仍生效」；编辑按统一判定 |
| `waiting_for_agent` | 强制发布（`desired≠0`，危险，二次确认） | 编辑、删除 | 说明任务在队列中 |
| `applying / pending / cleanup_pending` | 无（只读「部署中」） | 刷新、查看队列 | 编辑禁用 |
| `active_unconfirmed` | 重新强制发布（`desired≠0`） | 删除 | 标记「已强制发布，配置待确认」；编辑按统一判定 |
| `invalid / deleted` | 无 | 删除（invalid）/ 返回列表 | 只读；不显示编辑 |

**统一编辑判定**：仅当 `desired_revision_id === 0` 或状态 ∈ `{failed, active_failed, waiting_for_agent}` 时可编辑；否则按钮 `disabled`，悬浮说明「当前有在途发布，先完成或失败后再编辑」。该规则直接来自现有实现（`src/frontend/src/pages/Chains.tsx:490-500`），不要在详情页另造一套。

**拓扑面板**：入口→中间（0–2）→出口，最多 4 个节点；节点卡 200×104，间距 56；连接线 2px，端口标签在卡下方；节点显示序号、服务器别名、角色（入口/中转/出口）、状态、端口、共享入口标记、Agent 在线/离线、错误摘要（2 行）。线路色取 `--line-1..6`（具体色值由第 6 节定义），按稳定键 `chain:<id>` / `node:<id>` 哈希分配，跨列表、详情、面包屑一致；线色只用于 4px 标记与 2px 连接线，文字始终 ink，状态始终带文字，不以颜色单独表达（WCAG 1.4.11 图形对比 ≥3:1）。失败节点 1px 危险色边框 + 12% 危险色底；部署中节点用虚线边框 + 旋转点，尊重 `prefers-reduced-motion`。

**右栏「影响面」**：三行——直接分配（`chain_ids/node_ids`）、分组派生（用户分组 → 链路分组）、生效合计（`effective_chain_ids`，按 user.id 去重）；前两行不直接相加，合计单独计算。每行可点，跳 `/access/users?chain=<id>`。0 用户时显示「尚未分配给用户」+ 「分配用户」链接（去用户页并带 `chain` 筛选）。用户列表不可用时显示「影响面暂不可用」+ 重试，不显示 0。

**右栏「发布状态」**：显示 `published_revision_id`、`desired_revision_id`、`revision_forced`，以及 `revision_tasks` 的当前批次任务（apply/cleanup，pending/queued/acked/failed/abandoned），按失败优先排序，最多 10 条；每条可跳到相关服务器。**注意**：现有 API 没有 revision 历史列表，只有当前任务集合，因此这里叫「当前发布批次」，不叫「revision 时间线」；历史变更通过「查看操作日志」查询。这是对第 3.2 节「revision 时间线留下记录」的收敛，不改变目标。

**流量**：24h/7d 切换，数据来自 `/api/chain/get-traffic-history`；有效值与原始值同时存在时，默认显示有效值，倍率与原始值放在图例/悬浮中（现逻辑见 `src/frontend/src/pages/Chains.tsx:75-107`）。无数据时显示「暂无采样」，不画 0 线。

**诊断 tab**：`endpoint_status/endpoint_error`、逐跳错误、清理任务、待处理队列；不显示未提供的「命令详情」或「Agent 日志」。

**移动端**：状态头部不 sticky（高度降为 80），拓扑横向滚动（节点卡 180×96），右栏在主体下方堆叠，主操作固定在底部 56px 操作条；<1024 不显示「编辑拓扑」，改为「在桌面端编辑」说明。

**独立节点 `/network/nodes/:id`**：单节点拓扑 + 状态 + 服务器 + 端口 + 流量摘要 + 引用它的用户（按 `node_ids`）；动作仅「重试节点」「删除节点」（`src/frontend/src/pages/Chains.tsx:356-374`）。没有编辑 API，也没有 revision；不要渲染空的发布区。

#### 5.1.5 拓扑编排器 `/network/chains/new`、`/network/chains/:id/edit`

**入口**：链路列表主按钮「创建链路」；详情头部「编辑拓扑」；行菜单「编辑」。编辑入口遵循 5.1.4 的统一判定，禁用时给出原因。编排器使用**专注模式**：保留 56px 顶栏，隐藏左侧栏；左步骤栏 240、右校验/影响栏 360、中间画布 ≥720；内容最大 1600。顶部有「退出编排」与链路名；退出/浏览器后退/关闭标签页在有修改时都二次确认。

**步骤 1「画线路」**（`?step=topology`）：分段控件「直连 / 中转」；直连只有 1 台服务器（同时是入口与出口），中转为入口 + 0–2 中间 + 出口。服务器通过可搜索选择器加入，节点卡 220×88，支持拖拽重排与 `Alt+↑/↓` 键盘重排。实时校验（与现有提交前校验一致，`src/frontend/src/pages/chains/use-chain-form.ts:504-530`）：

- 1–4 台服务器；同一服务器不可重复；中转必须选入口与出口；
- 入口与中间跳必须具有入站能力（独立 IP，或 NAT 且有端口段）；仅出口档 NAT 只能作出口；
- 入口端口留空 = 自动；与现有链路共享监听时提示「将共享其入口参数」（`src/frontend/src/pages/chains/use-chain-form.ts:288-303`）；
- 逐跳地址留空 = 跟随服务器默认地址；非空值必须属于该服务器地址集合（后端同样校验）。
- 画布下方固定「校验摘要」：错误逐条带「定位到节点」；有错误时「下一步」禁用。

**步骤 2「定协议」**（`?step=protocol`）：分组为「基础」（名称模板 + 变量补全/预览）、「协议与端口」（协议、端口）、「传输与安全」（network/security 矩阵、Reality/TLS/Hysteria 条件字段）、「入口协议」（仅多跳；v1 固定 vless+reality；无入口端点的存量链锁定，见 `src/frontend/src/pages/chains/use-chain-form.ts:365-366`）、「流量倍率」。协议/安全/传输的联动纠偏沿用现有矩阵（`src/frontend/src/pages/chains/use-chain-form.ts:93-105,420-476`），选项变化时即时纠正并说明原因；高级项默认折叠。错误就地显示在字段下，提交时汇总到顶部并聚焦第一个错误。

**步骤 3「看影响再发布」**（`?step=impact`）：显示服务器序列、跳数、入口端口、出口协议、将影响的用户数（编辑时按当前分配计算；新建时为 0，明确写「创建后需在访问中分配用户」）、将被跳过的离线服务器（Agent 离线仍可排队，但标注「发布将等待 Agent」）。主按钮「发布」；点击后调用现有 `createChain/editChain`，拿到 `observeId` 后编排器进入只读「发布中」状态，由操作托盘同步阶段；成功进入详情，失败留在第三步并显示错误与失败跳。

**与第 3.3 节的一处修正**：现有 `/api/chain/create` 与 `/api/chain/edit` 会直接落库并下发任务（`src/frontend/src/pages/chains/use-chain-form.ts:655-684`），没有「保存为未发布」的 API。因此编排器只提供「发布」一个出口，不伪造草稿；若未来增加草稿能力，再恢复双出口。同理，第 3.2 节的「重试该跳」按现有 API 收敛为「重试链路」，失败跳通过拓扑定位，而不是逐跳独立重试。

**移动端**：<1024 显示只读说明页「链路编排需要 ≥1024px 的桌面窗口」，附当前链路摘要与「返回详情」；不把三步表单塞进 390px 宽度（与第 0.1 节一致）。

**可访问性**：所有节点选择与重排可用键盘完成；拖拽有等价按钮；校验摘要 `role="status"`；步骤切换不丢失焦点；颜色不作为唯一状态；按钮最小 44×44（触控），桌面 36×36 视觉尺寸配 44px 热区。

#### 5.1.6 网络域边界情况

| 情况 | 行为 |
|---|---|
| 检查器打开时对象被删/被过滤 | 轮询返回后移除 `sel`，保留筛选，列表头 `Notice`；焦点回到原行位置 |
| 详情打开时链路被删除 | 详情显示终止态横幅，停止轮询；保留「返回列表」与「查看已删除」 |
| 编排期间链路出现新发布 | 顶部横幅「该链路有新的发布任务」；禁用发布，要求刷新/重新打开，避免覆盖 |
| 两标签页同时编辑同一链路 | 无服务端锁；后提交方收到 API 错误，保留表单并显示 request_id；不自动重试写操作（现有 POST 不重试，`src/frontend/src/lib/requester.ts:242-300`） |

| 用户列表加载失败 | 影响面显示「未知」并提供重试；列表行的影响列显示 `--`，不写 0 |
| 1 跳 Chain 与独立 Node 同名 | 列表用类型标签区分，详情 URL 不同（chains vs nodes），命令面板结果带类型前缀 |
| 空列表 + 有筛选 | 显示「没有匹配的链路」+ 清除筛选；不显示「创建第一条链路」，避免误导 |

**排序与筛选**

- 默认「风险优先」：停用/到期 > 未生效 > 订阅异常 > 30 天内到期 > 其余，同组按到期升序；该排序由现有字段派生，无需后端（`假设` 排序权重可在 5.1 统一）。
- 可切换排序：名称、到期时间、用量合计、在线数；方向写 URL。现状无排序（`pages/Users.tsx:345-356`）。
- 筛选：状态多选、用户分组、订阅状态（ready/error/missing/pending）、到期窗口（7/30/90 天）、关键词（名称或数字 ID，不允许按 token 搜索）。每项筛选在 chip 上显示命中数；结果 0 时保留筛选条并提供「清除筛选」。
- 当前接口一次返回全部用户（`lib/api.ts:284-285`），A1 规模下客户端筛选可接受；超过 1000 用户时把筛选/分页下推服务端并启用行虚拟化（`P3`）。

**检查器规格**

1. 概要：名称、ID、创建时间、试用标记、用户分组；右上角「打开公开订阅页」外链。
2. 生命周期：生效时间、有效期、停用开关；到期用户提供「重新激活」（预填原配额与 +30 天有效期，复用 `pages/users/use-reactivate-user.ts:43-53`）；停用与启用都走操作托盘，不在原地乐观改状态。
3. 权限：直接链路 `chain_ids` 与生效链路 `effective_chain_ids` 分开展示；两者不一致时显示「由用户分组派生」提示；每条链路显示状态与 `access_uuid` 复制（`lib/types.ts:557-565`）。
4. 订阅：快照状态、revision、生成时间、来源、warnings 列表；「预览」支持 5 种格式 × 2 阶段（clash/singbox/quanx/quanx-config/links × final/pre，证据 `pages/Users.tsx:704-735`）；动作：重新生成、重置订阅地址、二维码、复制订阅地址/分享链接。
5. 外部订阅：模式（叠加/并入/仅节点）、额度、已用、剩余、合并后流量（`pages/Users.tsx:609-675`）。
6. 用量：当前周期 + 流量历史表（周期开始/上行/下行/合计，证据 `pages/Users.tsx:758-793`）；历史缺失时显示「暂无归档」而不是空图。
7. 活动：按用户过滤的操作日志；现有日志接口无 user_id 过滤（`lib/api.ts:555`），P2 先用关键词匹配并在标题注明「按名称匹配」（`假设`）。

**流程 A：新用户开通（目标 ≤5 步，复核页说明「有什么、没有什么」）**

1. 入口：用户页主按钮或 `⌘K` →「新建用户」。
2. 身份与时间：名称（必填）、试用开关、用户分组（可选）；生效「立即/定时」；有效期「长期/到期时间/按天数」。校验：试用必须设置试用流量或有效期（证据 `pages/users/use-create-user-form.ts:147-150`）；定时生效必须早于到期时间（`假设` 前置校验）。
3. 权限：选分组则链路由分组派生、直接链路选择器禁用并解释原因（`pages/users/CreateUserDialog.tsx:127-130`）；否则勾选直接链路；外部订阅逐项选模式。
4. 订阅策略：流量配额 + 重置日、套餐名、跳转链接、建议规则预设（极简/均衡/完整）或模板（`components/TemplateAssignmentTab.tsx:33-48`）。
5. 复核：显示「将生成 N 条链路（M 条 active）、X 个外部订阅；跳过 K 条并列出原因」；主操作「创建并发布」。影响面由链路 `status`、模板缓存与外部订阅状态派生；精确的订阅 warnings 只能创建后由快照返回，复核页只承诺结构预览（`假设` 无需新 API）。
6. 结果：订阅地址、分享链接、二维码、复制；快照 `pending` 时轮询到 `ready` 或 `error`，warning 逐条给出「去链路/去模板修复」的链接；创建接口返回 `observeId` 时进入操作托盘（`pages/users/use-create-user-form.ts:157-178`）。

**流程 B：订阅排障（一个页面内解释「为什么没节点」）**

1. 从值班板告警或用户搜索进入检查器「订阅」区，先读快照：`missing/pending/ready/error`、revision、generated_at、error、warnings（`lib/types.ts:604-611`）。
2. 按固定顺序跑 6 项诊断：已停用 → 已到期 → 未生效 → 试用流量用尽 → 无有效链路 → 快照 error/warnings；每项给出证据字段与一个修复动作，不让用户自己猜。
3. error/warnings 指向源对象：未发布 revision 的链路、缓存失败的模板、同步失败的外部订阅；能结构化的 warning 直接跳到对应检查器并保留返回路径（`假设`；若 warning 只有文本，则至少提供对象名与搜索入口，P2）。
4. 需要区分「生成失败」与「生成成功但部分条目被跳过」：前者展示 error，后者展示 warnings 列表（`pages/Users.tsx:739-747`）。
5. 修正后「重新生成」→ 操作托盘 → 成功后 revision +1；再打开 `/sub/:token` 验证节点数与状态（公开页规格见 5.4.3）。
6. 若怀疑链接泄露，走「重置订阅地址」：二次确认写明旧链接立即失效，成功后展示新地址与二维码（`pages/Users.tsx:223-244`）。

**状态与边界**

- 空列表、筛选无结果、接口失败三种空态文案不同；失败态保留重试按钮（现状只有顶部 Notice，`pages/Users.tsx:307`）。
- 用户可无链路创建成功，但复核页必须警告「订阅将包含 0 个节点」；快照可能生成成功但节点为 0，检查器必须把「0 节点」标为警告而不是正常。

## 6. 视觉语言

> 第 0 节把产品定为「线路值班台（Line Board）」：机群是站点，链路是线路，用户是通行证，订阅是时刻表。本节把这些比喻收束成可复用的形状、色彩、字体与节奏，并给出可直接进代码的数值；所有数值在第 7 节都有同名令牌（与第 0 节决策表一致）。
>
> 三条总原则：**母题只出现在对象身份位**，不进入操作控件；**一种颜色只承担一种职责**；**状态永远由形状 + 文字 + 颜色三重编码**。现有界面在这三点上恰好相反：红色同时是主操作、选中、模块索引与异常（`src/frontend/src/styles/panel.css:448-452`、`panel.css:839-844`、`src/frontend/src/pages/dashboard.css:143-157`、`src/frontend/src/lib/status.ts:17-19`），而 `degraded` 与 `failed` 都映射为红色（`status.ts:19`、`status.ts:17`）。

### 6.1 从概念到母题

| 母题 | 领域对象 | 视觉规则（尺寸/形状） | 出现位置 | 禁止 |
|---|---|---|---|---|
| **线路带** | 链路 Chain | 3px 宽、20px 高、2px 圆角，占行首身份槽；拓扑中为 3px 连线 | 链路列表行首、链路详情标题、订阅条目 | 整行填充线路色；线路色按钮 |
| **线路徽标** | 链路代号 | 20×20px、4px 圆角、1px 同色 40% 描边、10px Geist 600 代号 | 列表、详情、命令面板、订阅预览 | 只显示颜色不显示代号 |
| **站点标记** | 服务器 Server | 12px 圆环（1.5px 描边）+ 4px 核心；实心=独立 IP，空心=NAT | 拓扑、跳格、服务器地区列 | 用国旗或 emoji 代替站点 |
| **站序** | 跳 Hop | `01/02/03`，12px Barlow 600，16px 槽位，位于站点左上 | 拓扑、跳检查器、部署进度 | 用圆点数量表示跳序 |
| **通行证** | 用户 User | 24px 签发章（首字母、1px 描边）+ 16px 票根槽：2/2 虚线 + 6px 打孔 | 用户详情头部、用户检查器 | 每一行都做票根缺口 |
| **时刻表** | 订阅 Subscription | 36px 行、dt/dd 点状引导线、Barlow 时间与数量、右对齐 | 订阅分区、公开订阅页 `/sub/:token` | 用卡片网格代替时间列 |
| **值班板** | 待处理队列 | 56px 双行 + 56px 时间槽 + 行尾状态字形 + 单一主操作 | 值班板 | 顶部大数字英雄区 |

值班板一行的解剖（与上表同构，可作为评审时的视觉基准）：

```text
[3px 线路带] 08:12  HK-01 ──02── JP-02 ──03── US-01      降级 ▲   42 人   [重试该跳]
             56px   站点环12px + 站序12px（24px 步距）      字形+词   影响面   唯一主操作
```

**使用边界**（评审时可据此判定「过度设计」）：

- 母题只出现在对象身份位：行首、标题、拓扑。按钮、输入、菜单、表格分页不使用线路带或票根缺口。
- 同一视图最多两种母题：链路详情 = 线路 + 站点；用户详情 = 通行证 + 时刻表；值班板 = 值班板 + 线路。
- 所有母题都能用 ≤1.5px 描边画出；不使用渐变、玻璃、拟物或地铁实景插画。
- 颜色不是母题：去掉线路色，3px 带、20px 徽标与代号仍然成立（对应 6.2.4 的冗余要求）。
- 装饰不进入点击区：票根缺口、引导线、站序均设 `pointer-events: none`。

### 6.2 色彩体系

#### 6.2.1 四层职责

| 层 | 唯一职责 | 允许出现 | 禁止出现 | 现状证据 |
|---|---|---|---|---|
| 中性 | 结构、表面、文本 | 全部页面 | 用中性色表达状态 | 4 级表面 + 3 级文本已存在（`panel.css:18-45`） |
| **信号蓝** | 交互 | 主按钮、链接、选中、焦点、进行中 | 线路身份、图表分类、装饰 | 现由红色承担（`panel.css:448-452`、`:839-844`） |
| **线路色** | 链路身份 | 3px 带、20px 徽标、拓扑、链路相关图表 | 状态、按钮、正文 | 现状完全没有跨页身份色（`COMPONENTS` 无对应令牌） |

#### 6.2.2 中性色阶：暖纸与夜板

不采用 50–900 的数字灰阶：通用灰阶在深浅切换时需要反转编号，容易产生「dark 下 200 比 300 更深」的语义错误；现有 `--cg-*` 兼容别名（`panel.css:112-150`）已说明历史命名是负担。新系统只保留 **10 级语义阶**，每级只有一个结构含义，深浅两套各自给值。

|---|---|---|---|---|
| 底板 | 页面背景 | `#131210` | `#F2EDE3` | 1.07 / 1.10 |
| 表面 | 卡片、面板 | `#1B1916` | `#FBF8F1` | — |

| 主线 | 1px 分隔、卡片描边 | `#332F28` | `#DDD4C3` | 1.32 / 1.39（非文本） |

两条由此推出的硬规则：

- 表面与底板的亮度差只有 **1.07:1（深）/ 1.10:1（浅）**，因此卡片不能只靠色阶分层，必须有 1px `--panel-rule` 或 `--shadow-card`；这条直接约束第 8 节的布局实现。
- `ink-3` 在 `inset` 上只有 **4.38:1（浅）**，低于 4.5；凹陷背景里的正文与时间戳一律用 `ink-2`（6.22:1）。这是边界情况，不靠肉眼判断。

#### 6.2.3 信号蓝

信号蓝是唯一的交互色：主按钮、链接、焦点环、选中态、进行中状态。它与线路色刻意分开——蓝不在线路色板里（见 6.2.4），因此「蓝 = 可点」在本产品内没有歧义。

| 令牌 | 深色 | 浅色 | 用途 | 对比度 |
|---|---|---|---|---|
| `--panel-signal` | `#64B5FF` | `#0B5FCE` | 主按钮底、链接、焦点、选中指示、进行中 | 8.01 / 5.59（对 surface） |
| `--panel-signal-ink` | `#131210` | `#FFFFFF` | 信号底上的文字/图标 | 8.55 / 5.93 |
| `--panel-signal-soft` | `rgba(100,181,255,.14)` | `rgba(11,95,206,.08)` | 选中行底、命令面板高亮 | —（仅背景） |
| `--panel-signal-hover` | `#7CC2FF` | `#0A54B8` | 主按钮 hover | 10.1 / 7.0（对 surface，估算见 7.2） |

使用规则：

- **选中不用反白**：选中行 = 2px 信号蓝左条 + `signal-soft` 底色 + `ink` 文字；不做红底白字，也不做整行蓝底（现有反白选中见 `panel.css:839-844`）。
- **每屏主按钮 ≤1 个**；其余操作用 `--panel-control` 描边按钮，危险操作才用 `failed` 描边。
- 焦点环统一 `outline: 2px solid var(--panel-focus); outline-offset: 2px`；输入框同时把 border 切到信号蓝，不叠加发光。
- 唯一例外：**进行中**状态复用信号蓝（见 6.2.5），因为进行中总是由一次操作触发，它属于交互反馈而不是独立状态语义。

| L0 | 石墨 | `#6B645A` | `#A79E90` | 5.51 / 6.63 | 5.19 / 6.06 |

**校验结论**：9 色在两套外观、两种底色（surface / raised）下全部 ≥4.78:1，可直接用作 10px 代号文字与 3px 图形；不需要为文字单独准备深色版本。

**冗余编码（必须同时存在）**：

- 代号（L1…L8、L0）是主编码，颜色是加速识别；任何只显示颜色不显示代号的位置都判为不合规。
- 线型是第二编码，只有 3 种语义：**实线 = 已发布**；**长虚线 6/4 = 未发布/计划**；**点线 1/3 = 外部订阅**。线型不用于区分线路，避免 9 种 dash 无法记忆。
- 色觉校验：正常视觉下最小 ΔE76 为深色 24.4（L1/L8）、浅色 25.9（L3/L4）。Viénot 1999 红绿色觉模拟下最小 ΔE76 为深色 3.3（L1/L8）、浅色 4.0（L1/L3）——暖色在红绿色觉中会塌缩，这是数值事实，因此代号与站序不是可选装饰。评审时如看到「只画彩色线、不写代号」的稿子，直接退回。
- 不新增第 10 种线路色；超出 9 条时复用 L0 石墨（中性），而不是发明新色相（**假设 A7** 的边界）。

- **阈值与参考线**可以用状态色（1px 虚线 4/3），因为它们描述状态边界；状态色永远不做序列色。
- 禁止渐变填充、3D、发光、超过 2 层堆叠；canvas 文本用 `ink-2`，网格线用 `rule`。
- 现状冲突需一并消除：`costs-shared.tsx:35-64` 已经采用「中性阶梯 + 一处强调」并刻意避开状态色，但 `panel.css:99-100` 仍把 `--chart-3/4` 映射到 success/warning；新令牌直接移除这两个映射。

#### 6.2.7 色彩禁令

- 不用纯黑 `#000` / 纯白 `#FFF` 作为大面积表面；表面只用 6.2.2 的 10 级语义阶。
- 同一屏不使用超过 3 条线路色作为 >48px² 的填充面积；线路带和徽标不算。
- 不用颜色表达「选中」以外的第二含义；信号蓝不得出现在非交互元素上（进行中除外）。
- 不用红色做普通强调或删除以外的操作；「异常」与「删除」是它仅有的两个语义。
- 不在深色外观使用黑色半透明叠层模拟抬升；抬升靠 `raised` 与 1px 描边。
- 中文正文不使用 <12px 字号（见 6.3.3），也不使用彩色文字承载长句。

### 6.7 动效

动效只回答三个问题：什么发生了变化、变化发生在哪里、是否还需要等待。**只动 transform / opacity / color**，不动布局属性；首屏不引入 GSAP（现有依赖但非必需，`package.json`），签名动效用 CSS 完成。

| 场景 | 属性 | 时长 | 曲线 | 说明 |
|---|---|---|---|---|
| hover / focus | background-color、border-color | 80ms | standard | 不位移、不加阴影 |
| 按钮按下 | translateY(1px) | 80ms | standard | 只此一处位移 |
| 行选中 | 背景、左条 scaleY | 140ms | standard | 左条从中心展开，不整行闪白 |
| 对话框/抽屉 | opacity + translateY(8px) | 180ms | enter / exit | 关闭 140ms，遮罩同步 |
| 操作托盘 | translateY(100%) | 240ms | enter | 不阻塞页面，不遮罩 |
| 拓扑线路绘制 | stroke-dashoffset | 240ms + 40ms/跳 | standard | 最多 4 跳，总时长 ≤360ms |
| 状态切换 | 字形 cross-fade | 140ms | standard | 状态词立即替换，不做文字动画 |
| 读数更新 | 背景 flash（signal-soft） | 600ms 衰减 | linear | 数字不滚动、不弹跳 |

- 进行中的 270° 弧以 1.2s 线性旋转；`prefers-reduced-motion: reduce` 下改为静态 270° 弧 + 百分比文字。
- 减少动效时：所有时长按 0.01ms 处理（沿用 `index.css:531-538` 的策略），取消位移、缩放、错峰与循环动画；页面切换直接呈现。
- 性能：同屏动画元素 ≤20；不动画 `box-shadow`、`filter`、`backdrop-filter`；长列表只对进入视口的前 20 行启用入场。
- 动效不承担状态语义：即使关闭动效，「进行中」仍由形状 + 状态词表达。

## 7. 设计令牌

### 7.1 分层、命名与兼容

令牌分三层：**语义令牌**（组件唯一可消费的层）→ **组件局部变量**（组件内部派生）→ **原始值**（只出现在语义令牌定义里）。命名沿用仓库既有的 `--panel-*` 前缀，避免全站重命名；新增线路与状态角色，不新增主题维度。

| 旧令牌/写法 | 新令牌 | 处理 |
|---|---|---|
| `--panel-accent`（红） | `--panel-signal`（蓝） | 改值 + 改语义；主按钮、链接、焦点跟随 |
| `--panel-accent-soft` / `--panel-selection` | `--panel-signal-soft` | 合并；选中不再反白 |
| `--panel-success/warning/danger/info` | `--panel-status-ok/degraded/failed/waiting/unknown` | 增加形状与词表；`info` 不再作状态色 |
| `--chart-1..5` | `--panel-chart-1..5` | 只保留中性阶梯，移除 success/warning 映射 |
| `--radius: 2px`、`--radius-lg: 2px` | `--radius: 4px`、`--radius-lg: 12px` | 恢复真实圆角阶梯；组件写法与渲染一致 |
| `--cg-*` 兼容别名 | 无 | P3 删除；新组件不得引用 |

- 令牌名不包含具体颜色（禁止 `--panel-blue`），只包含角色（`--panel-signal`、`--panel-line-3`）。
- 断点不能写进 `var()`（CSS 限制，Tailwind v4 也一样），因此断点以 `@theme` 常量提供，不入运行时令牌表。

### 7.6 落地约束与验收

1. **禁止硬编码**：组件不得出现十六进制颜色、`px` 圆角、`box-shadow` 字面量；现有 `StatusBadge.tsx:12` 的 `#29282D`、`panel.css:657` 与 `login.css:36` 的 `#f7f7f2` 必须随重构清除。
2. **深浅等价**：每个新表面在加入前用两套外观各截一张图；只在一套外观成立的组件不允许合并。
3. **对比度门禁**：正文/状态词 ≥4.5:1（surface 与 raised 都要测）；UI 边界与焦点 ≥3:1；大字 ≥3:1。`ink-3` 不得用于 `inset` 背景上的正文（4.38:1）。
4. **状态三冗余**：任何状态必须同时有形状、状态词、颜色；评审时用灰度截图检查是否仍可读。
5. **字号门禁**：中文 ≥12px；拉丁机器码 ≥10px；Barlow 只用 600/700；Noto 只用 700/900。
6. **200% 缩放**：行高用 `min-height`，两套外观 + 五档宽度（1440/1280/1024/768/390）逐页检查不裁切、不横向溢出。
7. **减少动效**：`prefers-reduced-motion` 下无位移、无循环、无错峰；进行中改为静态弧 + 百分比。
8. **纹理与资源**：不引入新的外部字体、纹理或 CDN；线路/站点/状态图形全部内联 SVG（`docs/frontend.md` 的自托管约束）。
9. **建议的门禁实现**（P1，**假设 A6**）：在 `src/frontend/src/styles/` 增加一个不依赖浏览器的令牌对比度测试，读取设计令牌表并断言上述比例；CI 中与 `bun run test` 一起执行，避免后续改色悄悄破坏 AA。

## 9. 交互模式与变更安全流程

> 目标：让「改一条链路」和「删一台服务器」走同一条可预期、可回退、可审计的路径；让长操作不再夺走页面。核心判据：**观察完成不等于对象生效，文案必须由验证决定。**

### 9.1 风险分级与四步流程

| 级别 | 判定 | 例子（证据） | 必经步骤 |
|---|---|---|---|
| R0 浏览 | 无副作用 | 筛选、排序、打开检查器、预览订阅（`userSubscriptionPreview`） | 无 |
| R1 低 | 可重复、影响单对象 | 重试服务器测试、刷新模板列表、复制订阅 | 意图 + 即时反馈 |
| R2 中 | 改变线上配置或访问范围 | 创建/编辑/发布链路、批量指派模板、同步外部订阅、停用用户 | 四步 |
| R3 高 | 不可逆或影响面大 | 删除服务器/链路/用户、强制发布、重置订阅 token、恢复备份、升级、清空日志（`Settings.tsx`、`Chains.tsx`） | 四步 + L3 + 审计 |

| 步骤 | 用户问题 | 界面 | 必要数据 | 完成判据 | 失败与中断 |
|---|---|---|---|---|---|
| 1 意图 | 我要改什么 | 对象内对话框或编排器 | 对象、动作、范围 | 参数校验通过 | 留在意图层，字段级报错，不创建观察 |
| 2 影响预览 | 会影响谁、能否回退 | 内联区块、sheet 或对话框 | revision、用户/分组/订阅计数、逐跳 | 无阻塞项或已确认 | 阻止执行，给修复入口 |
| 3 执行 | 现在发生了什么 | 非阻塞操作托盘 | observe_id、阶段、百分比、警告 | 观察进入终态 | failed/lost 卡片 + 重新执行 + 审计 |
| 4 验证 | 真的生效了吗 | 状态条与托盘结果 | 对象最新状态 | 9.5 判据满足 | 「已提交，等待确认」+ 链接 |

- 影响预览只读，不创建观察（证据：校验失败不创建观察，`docs/superpowers/specs/2026-08-06-operation-progress-design.md`）。
- 托盘不阻塞；唯一保留的全屏阻断是面板自更新（`UpdateOverlay.tsx`）与认证过期。
- R3 不允许从命令面板直接执行；R2 可进入预览，但不得跳过预览。

### 9.2 意图（Intent）

- 入口：对象页主操作、行内溢出菜单、检查器动作区、命令面板。动作必须带对象与范围，禁止全局「删除」。
- 标题公式「发布链路『HK-JP-US』」「停用用户『lin』」；描述必须说明改什么、何时生效、能否回滚、影响多少对象（引用 9.3），四项缺一不得进入预览。
- 尺寸：单对象 480、批量 640；内边距 24；标题 20/1.3；正文 14/1.6；底部操作条 64 粘底；按钮 32（触屏 40）；圆角 12；移动端 sheet 90vh。
- 焦点：打开聚焦标题；R2 默认焦点主按钮；R3 默认焦点取消；Esc 关闭并返回触发元素；R1/R2 允许 Enter 提交，R3 必须显式点击。
- 校验：意图内同步完成；错误 12px + aria-describedby；聚焦首个错误；校验失败不进入预览、不创建观察。

### 9.3 影响预览（Impact Preview）

| 分区 | 必须回答 | 示例 |
|---|---|---|
| 变更摘要 | 改哪条对象、revision 如何变化 | 「链路 HK-JP-US：desired #12 → #13；3 跳」 |
| 影响对象 | 用户、分组、订阅、模板各多少 | 「用户 42（直接 17 / 分组派生 25）；分组 3；订阅 42」 |
| 服务影响 | 是否中断、哪一跳、顺序 | 「出口 → 入口逐跳下发；入口切换约 5 秒不可用（假设 A7）」 |
| 不可逆项 | 删除、token 重置、流量清零 | 「将删除 3 个出口节点，不可恢复」 |
| 阻塞项 / 数据时间 | 前置条件；计数基于何时数据 | 「JP-02 离线，可保存不能发布；基于 12:04:31 列表，30 秒内有效」 |

| 变更 | 计算 | 数据源 | 边界 |
|---|---|---|---|
| 发布/编辑链路 | 直接用户 = `chain_ids` 含该链路；分组派生 = `effective_chain_ids` 含该链路 | `/api/user/list`、`/api/link-group/list`、`/api/user-group/list` | 列表必须全部加载；任一失败标「无法计算」，不得按 0 处理 |
| 删除链路 | 同上，另加引用该链路的分组与外部订阅 | 同上 + `/api/external-subscription/list` | 外部订阅节点独立，不随链路删除 |
| 删除服务器 | 该服务器上的 hop → 受影响链路 → 用户与分组 | `/api/chain/list`、`/api/node/list`、`/api/user/list` | 离线仍可计算，但标「状态可能过期」 |
| 批量用户 | 选中数、已是目标态数量、将跳过数 | 当前列表 | 已停用/已删除项单独计数 |
| 服务器设置/升级 | 目标 revision 或版本、在线状态 | `Server.agent_settings_revision` 等 | 离线标「排队等待 Agent」 |

- 数字：能算就精确；0 写「0 位用户」；不能算写「无法计算」并说明缺哪份数据；只有抽样才用「约」并注明样本量。默认列前 5 个对象 + 「查看全部 42」。
- 放置：链路详情/编排器内联并随参数 250ms 防抖重算；列表行操作用 480 右侧 sheet；批量用 640 对话框。
- 状态：computing（骨架 3 行，延迟 150ms）、ready、blocked（禁用执行 + 修复链接）、stale（超过 30 秒）、error（说明失败数据源）。阻塞与过期不得只用颜色。
- 可访问性：打开聚焦标题；h3 + dl；重算完成 aria-live polite 播报「影响面已更新：42 位用户」；执行按钮 aria-describedby 指向阻塞原因。

### 9.4 执行：非阻塞操作托盘

**P1 交付边界**：现有 `OperationProgressProvider` 与 `operation-progress-state.ts` 是单 observeId 状态机（`src/frontend/src/lib/operation-progress-state.ts:5-49`）。P1–P2 按「同一时间只跟踪一个操作」交付（行为见 4.4）；本节的多卡堆叠为 P5 目标态，需要先改造状态层，不得在 P1 直接按多卡实现。

- 固定右下：right 24、bottom 24；折叠宽 360、展开 420；卡片间距 8；层级 40（Dialog 50）；移动端底部全宽 sheet。页面保持可滚动、可点击，无遮罩、不抢焦点；托盘有内容时页面底部预留 96px。
- 卡片：标题 14/600 单行截断 + 对象链接；状态 12px 文本 + 6px 点；阶段轨 4px、阶段名 11px；进度 12px tabular + 「3/5 用户」计数；消息 12/1.5 最多 2 行；动作 28px 高最多 3 个；警告折叠为逐条列表。
- 状态机：

| 状态 | 进入条件 | 呈现 | 动作 | 退出 |
|---|---|---|---|---|
| starting | 点击后至 observe_id 返回 | 「正在提交…」 | 无 | 收到 observe_id 转 running；8 秒无返回转「已提交，未返回进度」并停止等待 |
| running | 轮询返回 running | 进度与阶段实时更新 | 查看对象 | done/failed/lost |
| done / warning | status=done；有 warnings 时为 warning | 「已完成」或「完成，N 项警告」 | 验证结果、展开警告、审计 | 用户关闭 |
| failed | status=failed | 错误色 + 错误文案 | 重新执行、审计、查看对象 | 用户关闭 |
| lost | 轮询 404 | 「进度已丢失，操作可能仍在后台继续」 | 刷新对象、审计 | 用户关闭 |
| stale | 终态快照超过服务端 5 分钟 TTL | 保留最后快照并标「快照已过期」 | 查看对象、审计 | 用户关闭 |

- 堆叠：新操作在最下；同时只有一张展开（优先运行中最久的一条，否则最新）；最多显示 3 张，其余「+N 个操作」；会话内最多 5 条，超出淘汰最旧终态；终态 2 秒后自动收拢但不消失，不采用现有 1 秒自动关闭（`OperationProgressProvider.tsx` 的 AUTO_CLOSE_DELAY_MS）。刷新不恢复托盘（观察不持久化），后台操作继续。
- 重试：

| 级别 | 按钮 | 行为 | 保护 |
|---|---|---|---|
| R1 | 重新执行 | 原参数直接重发 | 防连点；显示 pending |
| R2 | 重新执行 | 重开影响预览，数据重算后提交 | 不允许跳过预览 |
| R3 | 重新执行 | 进入意图并重新完成 L3 | 禁止一键重试 |

- 不自动重试 POST：`requester.ts` 对 POST 只尝试 1 次，每次 POST 自动生成新 Idempotency-Key；手动重试是新请求，可能重复副作用。观察不可取消、不可重试（证据：设计文档「观察记录不是可操作的任务」），因此不提供「取消」，文案说明后台会继续。
- 同一对象已有 running 操作时主操作禁用并提示「该对象正在部署」；不同对象可并行，不排队、不合并。
- 审计：`/logs/operations?category=<category>&server_id=<id>&from=<startedAt-60s>&to=<finishedAt+60s>`，参数与 `api.operationLogs` 一致；done/warning/failed/lost 显示「审计」，running 只显示「查看对象」。日志条目暂无 observe_id（`OperationLogEntry` 字段），链接按对象与时间窗定位；日志未落库时提示「可能延迟数秒」，P3 再写 observe_id 与 trace_id。
- 轮询：500ms 起步，30 秒后 1s，2 分钟 2s；`document.hidden` 暂停，恢复可见立即拉取；404 转 lost；连续 3 次传输错误显示「连接中断，正在重试」但保持 running；复用 `OperationProgressProvider` 骨架，把单条状态改为按 observe_id 的集合，`operation-progress-state.ts` 按卡片复用。

### 9.5 验证（Verify）

| 操作 | 成功判据 | 数据源 | 超时 | 未确认时 |
|---|---|---|---|---|
| 发布/编辑链路 | status=active，published_revision_id = desired_revision_id，所有 hop=active | `/api/chain/list` | 30s | 「已提交，等待 Agent 确认」+ 逐跳状态 |
| 重试失败跳 | 目标 hop=active | 同上 | 30s | 保留失败跳高亮 |
| 删除链路/节点 | 对象从列表消失 | 同上 + `/api/node/list` | 10s | 「可能仍在清理」 |
| 强制发布 | active_unconfirmed 或 active，force 为真 | 同上 | 30s | 标注「尚未确认」 |
| 服务器设置 / 升级 | settings_status=synced 且 revision 相等；版本等于目标且命令 acked | `/api/server/list` + 命令日志 | 30/60s | 「等待 Agent 拉取」并保留命令 id |
| 用户停用/删除 | disabled=true 或用户消失 | `/api/user/list` | 10s | 保留 pending 标记 |
| 模板指派 / 外部同步 | 快照 revision 或时间前进；last_sync_at 前进且 last_error 为空 | `/api/user/list`、`/api/external-subscription/list` | 30s | 显示观察警告与最后错误 |

- 流程：终态 → 静默刷新一次 → 未满足则每 5 秒轮询至 30 秒 → 仍未满足显示「已提交，等待确认」，绝不写「已生效」。
- 「完成」只描述观察，「已生效」只描述验证通过；验证失败不是操作失败，保留警告态与审计链接，不自动回滚。
- 验证后让命令面板索引与列表缓存失效，避免用旧数据做下一次预览。

### 9.6 命令面板 ⌘K

| 分组 | 内容 | 执行 |
|---|---|---|
| 跳转 / 对象 | 五个一级入口、最近访问；服务器、链路、用户、分组、模板、外部订阅 | 直接导航；Enter 打开检查器或详情 |
| 创建 | 链路、用户、服务器 | 打开意图 |
| 安全操作 / 排除 | 重试、刷新模板、复制订阅；删除、强制发布、恢复备份、升级 | 仅 R1 直接执行；R3 不提供执行，只给「查看对象」 |

- 触发：⌘K / Ctrl+K 全局切换，顶栏按钮同效；不劫持输入框内普通按键；Esc 关闭并还原焦点。
- 尺寸：宽 640；距顶 12vh；最大高 min(560px, 70vh)；输入 48；分组头 28 粘顶；结果行 40；底部提示 36；圆角 12；实色表面 + overlay 阴影，不用毛玻璃；120ms 淡入，reduced-motion 取消位移。

- 索引：来源为已加载列表；打开时缓存超过 30 秒先刷新；用户上限 2000（假设 A9）；匹配名称、别名、ID、地址的小写包含；排序 exact > prefix > substring；每组最多 8 条、总共 20 条。
- 状态与可访问性：无查询显示最近 5 个对象 + 五入口；无结果显示「没有匹配」+ 创建入口；索引失败显示重试；离线用缓存 + 横幅。role=dialog + aria-modal；输入为 combobox，挂 aria-controls/expanded/activedescendant；结果 listbox/option；结果数 aria-live polite；背景 inert。

### 9.7 revision 时间线

- 位置：链路详情右栏，影响面下方；折叠显示最近 3 条，展开最多 20 条，「查看更多」跳操作日志。
- 来源必须可见：OpenAPI 没有 revision 历史端点（证据：`docs/openapi.yaml` 只有 create/edit 的 desired revision 描述），时间线由 `Chain.published_revision_id`、`desired_revision_id`、`revision_forced`、`revision_tasks` 与操作日志推导，标题旁标「由操作日志推导」。
- 条目：时间（time 元素）、动作（发布/强制发布/重试/清理）、revision（#12 → #12）、结果、逐跳任务、操作者、耗时、审计链接；revision 与任务来自链路对象，时间/操作者/结果来自 `OperationLogEntry`，本次托盘事件可即时插入一条「本地」，刷新后以日志为准。
- 状态：loading、empty（「创建或发布链路后出现」）、partial（日志不可用，仅显示当前 revision）、error；partial 必须说明缺哪部分，不补造中间 revision。
- 交互与边界：点击展开逐跳任务；可按结果或跳筛选；ol + 可聚焦条目；失败条目链接对应跳。不把 desired 显示成 published；强制发布单独标记；不生成不存在的序号。

### 9.8 批量选择与危险操作确认

- 选择：首列 40px、复选框 16px、命中区 44px；表头三态；Shift 连选；⌘/Ctrl 点选；Esc 清空；只在列表挂载期间保留，不写入 URL。选择栏高 56、底部 24 居中、最大宽 720、圆角 12、overlay 阴影；显示「已选 12 · 其中 3 项不在当前筛选」；小于 1280 时位于托盘上方。
- 批量语义必须如实标注，不得把循环调用说成原子操作：

| 动作 | 调用 | 语义 | 级别 | 确认 | 部分失败 |
|---|---|---|---|---|---|
| 指派/取消模板 | `/api/subscription/template/assign`，user_ids[] | 单请求，真实批量 | R2 | L2 | 观察 warnings 逐用户列出 |
| 加入用户分组 | `userGroupUpdate` 替换 user_ids（假设 A8） | 单请求，覆盖成员 | R2 | L2 | 重新拉取后逐项对比 |
| 启用/停用 | `/api/user/update` 逐个 | 串行，最多 3 并发 | R2 | L2 | 逐项结果，失败不回滚成功项 |
| 删除用户 | `/api/user/delete` 逐个 | 串行，不可逆 | R3 | L3 | 逐项结果，停止或继续在意图中选定 |
| 删除链路 | `/api/chain/delete` 逐个 | 串行，每项一个观察 | R3 | L3 | 托盘合并为一张「批次卡片」显示 x/n |

- 批量执行统一用一张「批次卡片」（如「批量停用用户 · 3/12」），内部逐项结果；底层仍是单个请求与观察，不伪造服务端批次任务。
- 危险确认三级：L1 行内（可撤销或可重跑，二次点击或 5 秒撤销条，焦点原位）；L2 对话框（删除单对象、停用用户、重置流量，默认焦点取消）；L3 输入确认（删除服务器/链路、强制发布、恢复备份、重置 token，必须输入对象全名才启用主按钮，焦点在输入框）。
- L3 细节与安全：autocomplete=off；不预填；不匹配时 disabled 并说明「名称不一致」；Enter 匹配前不提交；Esc 取消；错误用 aria-describedby；提交中禁用主按钮；关闭后焦点回触发元素；破坏性按钮不自动聚焦；文案必须含对象名、影响数、是否可逆；已是目标态的条目显示「将跳过 N 项」且不计入影响数。

### 9.9 加载、空、错误、离线与部分失败

| 模式 | 呈现 | 动作 | 文案 | 可访问性 |
|---|---|---|---|---|
| 首载 | 与最终布局同几何的骨架；150ms 延迟、300ms 最短 | 无 | 不用「加载中…」占满整页 | aria-busy；role=status |
| 刷新 | 保留旧数据 + 更新时间 | 手动刷新 | 「更新于 12:04:31」 | 不抢焦点 |
| 空（首次） | 图标、标题、原因、主操作 | 创建或导入 | 「还没有链路。先创建一条，或从模板导入。」 | 标题层级 |
| 空（筛选） | 已选条件 chips + 清除 | 清除筛选 | 「没有符合条件的结果」 | 说明筛选条件 |
| 错误 | 区块级错误卡 + request_id | 重试、复制诊断 | 「读取失败，已重试 3 次」 | role=alert，焦点不跳 |
| 离线 | 顶栏 40px 横幅 + 最后数据时间 | 重连；禁用 R2/R3 | 「连接中断，显示 12:04:31 的数据」 | role=status；恢复播报 |
| 部分失败 / 过期 | 失败区块就地提示；时间戳 + 过期标记 | 仅重试失败区块；刷新 | 「3 个区块中 1 个失败」「数据可能已过期」 | 汇总可朗读 |

- 错误分类：business（后端业务码）字段或区块内联并保留输入，修正后手动重试；transport（网络、超时、HTTP）横幅或区块错误并保留最后数据，自动 3 次 + 手动；protocol（响应格式异常）错误卡 + request_id，手动重试；cancelled（卸载或主动取消）不提示、不重试。
- 失败不得清空整页：只有全部区块失败才升级为页面错误；单区块失败保留其余内容。
- 认证过期是跳转登录，不作为页面错误；离线时 R2/R3 主操作禁用并给出原因，而不是提交后报错。

### 9.10 轮询反馈与乐观更新边界

| 表面 | 间隔 | 隐藏时 | 停止条件 |
|---|---|---|---|
| 操作托盘 | 500ms → 1s → 2s | 暂停 | 终态或 lost |
| 值班板 / 网络列表 | 10s | 暂停 | 卸载 |
| 访问列表 | 15s | 暂停 | 卸载 |
| 运行监控 | 5s | 暂停 | 卸载 |
| 成本 | 60s | 暂停 | 卸载 |
| 日志 / 面板状态 | 手动，或自动刷新 15s；面板 5s（现状 `Layout.tsx`） | 暂停 | 卸载 |

- 反馈分层，禁止重复：顶部 2px 请求条只表示前台请求（`Layout.tsx` 的 foregroundPendingCount）；托盘只表示被观察的长操作；行内 pending 只表示单次变更；骨架只表示首载；Toast 只表示 3 秒确认；横幅只表示全局离线或面板更新。
- 允许乐观更新：外观、密度、导航折叠、页签、筛选 chip 与 URL、复制反馈；失败只回滚局部状态，不伪造服务端结果。
- 禁止乐观更新：链路/服务器/用户状态、revision、订阅快照、设置持久化、成本与计费、任何 R2/R3 操作。
- 变更中的行用「最后确认状态 + pending 标记」（如「正常 · 部署中」），不得提前显示「正常」或「已停用」；响应后重新拉取，失败只移除 pending 并就地报错。
- 幂等与并发：POST 只尝试 1 次，每个 POST 自带 Idempotency-Key（`requester.ts`）；手动重试是新键，R2/R3 必须先重算影响面。所有新轮询复用 `usePolling` 的 AbortController 与 requestRef 序号守卫；页面隐藏暂停，恢复可见且超过间隔时立即刷新。
- 屏幕阅读器：阶段变化与终态播报，百分比不逐跳播报；aria-live 用 polite，只有失败用 assertive。

### 9.11 验收口径

- 任意 R2/R3 变更都能从托盘回到对象，再跳到对应时间窗的审计记录。
- 观察 done 但对象未满足判据时，界面任何位置都不出现「成功」「已生效」。
- 影响预览为 0 时明确写「0 位用户」；无法计算时写「无法计算」并说明缺哪份数据。
- 断网 30 秒再恢复：不整页报错、不重复弹错、不丢失已填表单；批量部分失败逐项可见，绝不显示「全部成功」。
- 仅用键盘可完成：⌘K 找对象 → 选中 → 预览 → 确认 → 关闭托盘。

### 10.2 键盘、焦点与朗读

| 按键 | 作用域 | 行为 |
|---|---|---|
| Tab / Shift+Tab | 全局 | 顺序：跳过链接 → 侧栏 → 顶栏 → 主内容；浮层打开时限制在浮层内 |
| ↑ / ↓ | 列表、菜单、命令面板 | 列表用 roving tabindex 移动真实焦点；命令面板移动高亮；Home/End 到首尾 |
| Enter | 行、菜单项、按钮 | 打开检查器/详情；L3 危险提交不响应 Enter，必须显式点击 |
| Space | 复选、行选择 | 切换选中，不滚动页面；表头三态（全选/部分/无） |
| Esc | 最上层浮层 | 关闭检查器/对话框/托盘/命令面板，焦点回触发元素；不关闭页面 |
| ⌘K / Ctrl K | 全局 | 打开命令面板；输入框内同样生效（组合键不违反 2.1.4） |
| / | 主内容聚焦时 | 聚焦当前页搜索框；不在文档级监听，避免误触 |
| Alt+↑ / Alt+↓ | 编排器节点 | 键盘重排，与拖拽等价（2.5.7） |
| PageUp / PageDown | 命令面板、表格 | 翻页/滚动；不与分页按钮抢焦点 |

焦点规则（实现约束）：

1. **焦点环唯一**：`outline: 2px solid var(--panel-focus); outline-offset: 2px`；不在父容器裁切（检查器、表格容器 `overflow` 需留 2px 内距）。
2. **落点**：路由切换后焦点落到新页 h1（`tabIndex={-1}`）并更新 `document.title`；读屏不整页重读，只播报标题。
3. **返回**：检查器/对话框关闭后焦点回触发元素；对象被删除导致触发元素消失时，焦点落到列表容器并播报「对象已删除」。
4. **sticky 遮挡**：所有可聚焦元素 `scroll-margin-block: 96px`；顶栏 56 + 吸顶表头 36 是固定值，不随页面变化。
5. **托盘**：不抢焦点、不设遮罩；卡片状态用 `aria-live="polite"`，失败用 assertive；展开/收起按钮 ≥44×44，Esc 收起并回按钮。
6. **表格行**：整行点击是鼠标便利，键盘用行内「打开」按钮；不把 `<tr>` 改成 `role="button"`，保留表格语义。

朗读与语义：

- 地标：`header` / `nav aria-label="主导航"` / `main` / 检查器 `aside aria-label="服务器检查器"`；现状只有 `main`（`Layout.tsx:287`），其余需补。
- 表格：`<caption class="sr-only">`；数值与单位同一文本节点（「42 位用户」），不拆成两个 span；`tabular-nums` 不影响朗读。
- 状态：状态词固定为「通行 / 部署中 / 降级 / 异常 / 待确认 / 未知」（第 6.2.5 节）；颜色与字形只作加速。
- 图表：canvas `aria-hidden="true"`，同级提供摘要（「过去 24 小时总流量 1.2 TB，峰值 12:00」）与「查看数据表」按钮；不把 canvas 设为可聚焦。
- 拓扑：`<ol aria-label="链路 HK-JP-US 的 3 跳">`，每项文本「02 JP-02 中转 部署中」；连接线 `aria-hidden`。
- 复制：按钮名「复制订阅地址」，成功后 `aria-live` 播报「已复制」，2 秒后清除；不依赖 Toast。
- 时间：`<time datetime>`；时区在页头统一说明，不逐条重复。
- 机器码：代号（L1）、协议（VLESS）、端口（443）加 `lang="en"`；中文标题不做全大写。

### 10.3 减少动效、缩放与对比模式

| 场景 | 默认 | `prefers-reduced-motion: reduce` |
|---|---|---|
| 页面/浮层进入 | 180–240ms，`translateY(8px)` | 直接呈现，仅保留 opacity（≤1ms） |
| 进行中 270° 弧 | 1.2s 线性旋转 | 静态 270° 弧 + 百分比文字 |
| 拓扑线路绘制 | 240ms + 40ms/跳 | 一次呈现，无 dash 动画 |
| 状态切换 | 140ms 字形 cross-fade | 立即替换 |
| 读数更新 | 600ms 背景 flash | 无 flash，数字直接替换 |

- 全局已在 `index.css:531-539` 把动画/过渡压到 `0.01ms`；新组件必须在该规则下仍可读（不靠动画表达状态）。

- `prefers-contrast: more`：移除纸纹、`rule` 提升为 `rule-strong`、禁用状态 wash；`forced-colors` 下依赖边框与系统色，不覆盖 `ButtonText`/`Highlight`。

### 11.3 令牌落到 Tailwind v4 的步骤

1. **建令牌文件**：新增 `src/frontend/src/styles/tokens.css`，按第 7 节在 `:root`（暖纸）与 `.dark`（夜板，默认）各定义一次；保留 `--cg-*` 作为过渡别名，不新增。

3. **接管 shadcn 语义别名**：`--background/--foreground/--card/--border/--primary/--ring/--radius` 指向新令牌；删除 `panel.css:97-101` 中 `--chart-1..5` 对 accent/success/warning 的映射，改为第 7.2.5 节的中性阶梯。

5. **组件迁移顺序**：button/input/select/tabs → table/badge → card/dialog/sheet → 新增 kit。每步只改令牌与尺寸类，不改业务逻辑；每步跑 `format:check / test / lint / build` 与两外观截图。

### 11.4 设计系统治理

- **单一事实源**：`tokens.css` + 第 7 节表；`DESIGN.md` 当前仍是旧「红色索引标签 + 2px 直角」语言，P0 起标记为 deprecated，P5 重写为新语言，避免两份规范并存。
- **变更纪律**：令牌 PR 必须含对比度断言结果、两套外观截图、受影响页面清单、迁移说明；新增令牌需写明「角色 + 唯一职责」，禁止颜色名。
- **组件准入**：新组件先进 `components/kit/`，必须带 loading/empty/error/stale 四态与键盘说明；页面不得新写一次性控件（第 8.1 节）。
- **例外审批**：只有数据可视化可越过密度令牌；hex、px 圆角、`box-shadow` 字面量由 lint 脚本拒绝（第 7.6 节）。
- **废弃节奏**：`--cg-*` 冻结、只减不增；`--panel-accent` 作为 signal 的过渡别名保留一个阶段，P5 删除；不恢复任何主题注册表（`themes/` 目录当前已不存在）。
- **文档节奏**：每个 Phase 结束回写本文对应小节的「现状证据」与截图目录；发布说明记录令牌变更与新增组件。
