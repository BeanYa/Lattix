## 5.2 访问域：用户 / 分组 / 订阅模板 / 外部订阅

> 本节承接第 4 节信息架构、6–7 节视觉令牌与 5.1 的全局框架，只定义页面内部结构。证据路径均相对 `src/frontend/src/`；`假设` 表示未被现有代码/文档证实的设计判断；`P2` 表示需安全评审或前端增强，`P3` 表示需要后端新增查询或字段。路由 slug 以第 4.3 节路由表为准。

**访问域共用契约**

- 四个页面都是「列表 + 检查器」：≥1440px 检查器宽 400px，1280–1439px 为 376px，1024–1279px 改为 480px 覆盖抽屉，<1024px 改为整页详情；关闭后回到原滚动位置与筛选（沿用 5.1 的深链接规范）。
- 列表状态写入 URL：`?q=&status=&group=&sort=&dir=&selected=`；刷新、分享、后退必须可复现（现状用户页无筛选，日志等筛选也只存在组件 state，证据 `pages/Users.tsx:85-118`、`pages/OperationLogs.tsx:97-117`）。
- 行高默认 44px、紧凑 36px；表头 32px；单元格左右内边距 12px；数字右对齐并使用等宽数字（1.5 节 #6 的 44/36 规格）。
- 空态、加载、错误、只读四种状态共用 5.1 的组件；轮询失败时保留上一份数据并显示「数据时间」，不把表格清空（现状外部订阅仅整体 loading，证据 `pages/ExternalSubscriptions.tsx:254-262`）。

### 5.2.1 用户（`/access/users`）

**职责**：发放通行证——建用户、定期限、给链路、发订阅、解释「为什么没有节点」。现状是单表 8 列、无搜索/筛选/排序/分页，所有操作分散在多个 Dialog（创建、查看链路、订阅设置、结果预览、流量历史、二维码；证据 `pages/Users.tsx:309-356`、`pages/Users.tsx:557-794`）。

**表格列（1440px）**

| 列 | 宽度 | 内容与规则 | 证据 |
|---|---|---|---|

响应式：1280 隐藏「在线」；1024 隐藏「链路」并把用量压到 160；<768 改为两行卡片（第一行名称+状态，第二行用量/到期/链路，点按 44px 打开检查器），不横向滚动。

**排序与筛选**

- 默认「风险优先」：停用/到期 > 未生效 > 订阅异常 > 30 天内到期 > 其余，同组按到期升序；该排序由现有字段派生，无需后端（`假设` 排序权重可在 5.1 统一）。
- 可切换排序：名称、到期时间、用量合计、在线数；方向写 URL。现状无排序（`pages/Users.tsx:345-356`）。
- 筛选：状态多选、用户分组、订阅状态（ready/error/missing/pending）、到期窗口（7/30/90 天）、关键词（名称或数字 ID，不允许按 token 搜索）。每项筛选在 chip 上显示命中数；结果 0 时保留筛选条并提供「清除筛选」。
- 当前接口一次返回全部用户（`lib/api.ts:284-285`），A1 规模下客户端筛选可接受；超过 1000 用户时把筛选/分页下推服务端并启用行虚拟化（`P3`）。

**检查器规格**

1. 概要：名称、ID、创建时间、试用标记、用户分组；右上角「打开公开订阅页」外链。
2. 生命周期：生效时间、有效期、停用开关；到期用户提供「重新激活」（预填原配额与 +30 天有效期，复用 `pages/users/use-reactivate-user.ts:43-53`）；停用与启用都走操作托盘，不在原地乐观改状态。
3. 权限：直接链路 `chain_ids` 与生效链路 `effective_chain_ids` 分开展示；两者不一致时显示「由用户分组派生」提示；每条链路显示状态与 `access_uuid` 复制（`lib/types.ts:557-565`）。
4. 订阅：快照状态、revision、生成时间、来源、warnings 列表；「预览」支持 5 种格式 × 2 阶段（clash/singbox/quanx/quanx-config/links × final/pre，证据 `pages/Users.tsx:704-735`）；动作：重新生成、重置订阅地址、二维码、复制订阅地址/分享链接。
5. 外部订阅：模式（叠加/并入/仅节点）、额度、已用、剩余、合并后流量（`pages/Users.tsx:609-675`）。
6. 用量：当前周期 + 流量历史表（周期开始/上行/下行/合计，证据 `pages/Users.tsx:758-793`）；历史缺失时显示「暂无归档」而不是空图。
7. 活动：按用户过滤的操作日志；现有日志接口无 user_id 过滤（`lib/api.ts:555`），P2 先用关键词匹配并在标题注明「按名称匹配」（`假设`）。

**流程 A：新用户开通（目标 ≤5 步，复核页说明「有什么、没有什么」）**

1. 入口：用户页主按钮或 `⌘K` →「新建用户」。
2. 身份与时间：名称（必填）、试用开关、用户分组（可选）；生效「立即/定时」；有效期「长期/到期时间/按天数」。校验：试用必须设置试用流量或有效期（证据 `pages/users/use-create-user-form.ts:147-150`）；定时生效必须早于到期时间（`假设` 前置校验）。
3. 权限：选分组则链路由分组派生、直接链路选择器禁用并解释原因（`pages/users/CreateUserDialog.tsx:127-130`）；否则勾选直接链路；外部订阅逐项选模式。
4. 订阅策略：流量配额 + 重置日、套餐名、跳转链接、建议规则预设（极简/均衡/完整）或模板（`components/TemplateAssignmentTab.tsx:33-48`）。
5. 复核：显示「将生成 N 条链路（M 条 active）、X 个外部订阅；跳过 K 条并列出原因」；主操作「创建并发布」。影响面由链路 `status`、模板缓存与外部订阅状态派生；精确的订阅 warnings 只能创建后由快照返回，复核页只承诺结构预览（`假设` 无需新 API）。
6. 结果：订阅地址、分享链接、二维码、复制；快照 `pending` 时轮询到 `ready` 或 `error`，warning 逐条给出「去链路/去模板修复」的链接；创建接口返回 `observeId` 时进入操作托盘（`pages/users/use-create-user-form.ts:157-178`）。

**流程 B：订阅排障（一个页面内解释「为什么没节点」）**

1. 从值班板告警或用户搜索进入检查器「订阅」区，先读快照：`missing/pending/ready/error`、revision、generated_at、error、warnings（`lib/types.ts:604-611`）。
2. 按固定顺序跑 6 项诊断：已停用 → 已到期 → 未生效 → 试用流量用尽 → 无有效链路 → 快照 error/warnings；每项给出证据字段与一个修复动作，不让用户自己猜。
3. error/warnings 指向源对象：未发布 revision 的链路、缓存失败的模板、同步失败的外部订阅；能结构化的 warning 直接跳到对应检查器并保留返回路径（`假设`；若 warning 只有文本，则至少提供对象名与搜索入口，P2）。
4. 需要区分「生成失败」与「生成成功但部分条目被跳过」：前者展示 error，后者展示 warnings 列表（`pages/Users.tsx:739-747`）。
5. 修正后「重新生成」→ 操作托盘 → 成功后 revision +1；再打开 `/sub/:token` 验证节点数与状态（公开页规格见 5.4.3）。
6. 若怀疑链接泄露，走「重置订阅地址」：二次确认写明旧链接立即失效，成功后展示新地址与二维码（`pages/Users.tsx:223-244`）。

**状态与边界**

- 空列表、筛选无结果、接口失败三种空态文案不同；失败态保留重试按钮（现状只有顶部 Notice，`pages/Users.tsx:307`）。
- 用户可无链路创建成功，但复核页必须警告「订阅将包含 0 个节点」；快照可能生成成功但节点为 0，检查器必须把「0 节点」标为警告而不是正常。
- 定时生效未到、到期、停用可叠加：状态列按优先级只显示最靠前两项，完整原因放检查器。
- 预览请求失败不能覆盖已显示的旧内容；切换格式/阶段时保留旧内容并显示局部 loading（现状会清空，`pages/Users.tsx:246-260`）。
- 订阅链接是凭证：表格与检查器默认只显示域名 + token 前 4 位（`假设` 新的脱敏规范；现状明文显示，`pages/Users.tsx:448-449`）。
- 重置 token、删除用户、停用用户都需影响预览与二次确认；删除后旧订阅地址返回 404（公开页按此处理）。

### 5.2.2 分组：链路分组 / 用户分组（`/network/link-groups`、`/access/user-groups`）

**职责**：把链路与外部订阅编成「线路包」，再发给一批用户。两类分组是两种对象，不是两种视图；重构后拆成两个独立页面（链路分组归网络域，用户分组归访问域），不再共用 tab（`pages/Groups.tsx:80-96`）。

**密度与分区**：页头 64px + tab 40px + 左列表（1fr）/右检查器（400→376→480 覆盖→整页）；列表行 44px；分组名 15px/600，计数用 12px chip；首屏可见 8–10 组。

**链路分组表**：名称（1fr，最小 220）/ 链路数 88 / 外部订阅数 112 / 被用户分组引用 1fr（最多 2 个 chip +「+N」）/ 操作 88。可排序：名称、链路数、引用数；可筛选：未被引用、含外部订阅、名称搜索。证据字段 `lib/types.ts:1110-1119`。现状为行内 chip 列表、无排序筛选（`pages/Groups.tsx:175-205`）。

**用户分组表**：名称 1fr / 成员数 88 / 链路分组数 112 / 派生链路数 112 / 派生外部订阅数 112 / 操作 88。派生数由关联链路分组求和（`假设` 客户端可算，数据来自 `lib/types.ts:1128-1136`）；可排序成员数；筛选「空分组」「成员已停用」。

**检查器**：名称、链路多选（带搜索与状态；只能选共享入口链路，证据 `pages/Groups.tsx:310`）、外部订阅多选 + 模式（叠加/并入/仅节点，`pages/Groups.tsx:339-377`）、影响预览「影响 M 位用户 · 将重发布 N 份订阅」（`假设` 由成员数与快照状态派生）、保存（操作托盘）。用户分组检查器：成员多选、关联链路分组、独占约束提示——一个用户只能属于一个分组，编辑时隐藏其他分组成员（`pages/Groups.tsx:534-546`）。

**状态与边界**：空分组允许存在但标记「未使用」；删除被引用的链路分组时列出引用它的用户分组与受影响人数，确认后才允许删除（现状只给一句描述，`pages/Groups.tsx:132-149`）；外部订阅额度未知时显示「未知」而不是 0；链路非 active 仍可加入分组，但显示状态并在影响预览里计入「可能不生效」；模式变更会改变用户额度合并结果，保存前必须展示合并前后对比（`假设`）。

**职责**：分流规则模板的缓存与版本管理，不负责直接生成订阅。类型 5 种、来源本地/GitHub、可只读、可克隆（`pages/SubscriptionTemplates.tsx:40-46`、`lib/types.ts:636-651`）。

**密度与分区**：页头 64px（右侧「刷新全部」「新建模板」）+ 工具条 48px + 单表；无检查器，预览用 720px 抽屉；行高 44px；首屏 12–14 行。

**表格列**：模板 240（名称 + ID 等宽）/ 类型 120 / 来源 120（GitHub/本地 + 只读）/ 缓存 200（状态 + 时间）/ 许可证 120 / 引用用户 96 / 操作 144。1024px 以下隐藏许可证与来源；<768 卡片化（名称、类型、缓存状态、主要动作）。

**排序与筛选**：名称、缓存时间、引用用户数；类型多选、来源、缓存状态（已缓存 / 刷新失败 / 本地内容 / 尚未缓存）、引用状态。引用数从用户的 `routing.assigned_*_template_id` 汇总并按用户去重（证据 `components/TemplateAssignmentTab.tsx:87-100`），当前列表没有该列（`pages/SubscriptionTemplates.tsx:209-219`）。

**详情抽屉**：元数据（kind/origin/source_url/content_sha256/license/fetched_at/last_attempt_at/last_error）+ 只读代码预览（不填充用户与链路数据，证据 `pages/SubscriptionTemplates.tsx:399-408`）+ 动作：刷新（仅 GitHub）、克隆、编辑、删除（只读模板无编辑/删除，`pages/SubscriptionTemplates.tsx:294-313`）。抽屉宽 720px，代码区使用等宽 11px、行高 1.5、可复制；超过 2000 行时默认折叠并提示。

**状态与边界**：刷新失败沿用旧缓存，必须同时显示「刷新失败」和上次成功时间（`pages/SubscriptionTemplates.tsx:243-258`）；缓存为空时不可被指派（`components/TemplateAssignmentTab.tsx:438-440`）；GitHub 地址只接受公开具体文件（`pages/SubscriptionTemplates.tsx:362-369`）；删除被引用模板前列出引用用户并禁止静默失败；克隆默认命名为「原名 副本」并直接进入编辑（现状如此，`pages/SubscriptionTemplates.tsx:139-147`）。

**批量指派**：保留在用户页二级 tab（现状 `pages/Users.tsx:309-317`），模板检查器提供「去指派」跳转；步骤为「勾选用户 → 建议规则（极简/均衡/完整/自定义）或模板 → 是否强制覆盖 → 影响预览（N 人、格式覆盖）→ 指派」。强制覆盖后用户自选失效，必须在预览中写明（证据 `components/TemplateAssignmentTab.tsx:444-452`）。

### 5.2.4 外部订阅（`/access/external-subscriptions`）

**职责**：导入第三方订阅、按间隔同步、观察额度与错误。现状是垂直卡片列表，每张卡 4 个指标（`pages/ExternalSubscriptions.tsx:263-355`）。

**密度与分区**：页头 64px + 工具条 48px（搜索、状态筛选、新建）+ 表体；检查器 400px；行高 44px；首屏 10–12 行。移动端改为卡片：名称 + 节点数 + 额度条 + 同步时间 + 状态。

**表格列**：名称 200 / 格式 96 / 节点 72 / 流量 200（已用 = 上行 + 下行，除以总额；现卡片只看 `download/total`，`pages/ExternalSubscriptions.tsx:321-331`，本方案改为上下行合计）/ 到期 144 / 同步 160（自动开关 + 间隔）/ 上次同步 160 / 状态 96 / 操作 88。1280 隐藏格式；<1024 卡片化（保留节点数、额度条、同步状态与到期）。

**排序与筛选**：节点数、额度使用率、上次同步、到期；筛选项：同步失败（`last_error` 非空）、自动同步关闭、额度未知（`total=0`）、7/30 天内到期。默认按「同步失败 → 额度使用率 ≥90% → 名称」排序（`假设` 同用户页风险排序）。证据字段 `lib/types.ts:1072-1091`。

**检查器**：URL（凭证，默认脱敏，需显式「显示」+ 复制）、User-Agent 预设与自定义、跳过证书校验、自动同步与间隔 1–168 小时（`pages/ExternalSubscriptions.tsx:442-453`）、格式、最近尝试/成功时间、错误详情、节点表（名称/协议/服务器:端口/配置指纹前 8 位，`pages/ExternalSubscriptions.tsx:484-512`）、动作「立即同步」「删除」。同步走操作托盘，期间禁用重复点击并显示当前阶段。

**状态与边界**：`total=0` 表示额度未知而非 0；`expire` 为空显示「-」；删除订阅会连同导入节点一起移除，确认文案必须写明；UA 不被服务商接受时可能返回 406，错误区给出「换 UA 预设」的建议（`pages/ExternalSubscriptions.tsx:417-419`）；自动同步关闭时间隔输入禁用；长时间未同步显示「已过期 N 天」而不是只显示日期（`假设` 视觉提示，不改数据）；同步中关闭页面由托盘继续并可从值班板查看结果。

## 5.3 运行域：运行监控 / 成本 / 日志

### 5.3.1 运行监控（`/run/console`）
